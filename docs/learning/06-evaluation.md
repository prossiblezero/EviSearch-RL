# 06：一张表怎么才能相信

先看 [results/README.md](../../results/README.md)，再读 [evaluate.py](../../evisearch/evaluate.py)、[evaluation/compare.py](../../evisearch/evaluation/compare.py) 和 [report.py](../../report.py)。

## 两种入口不要混淆

`python report.py` 读取已有真实预测、校验并重算当前公开摘要，不加载模型。`python -m evisearch.evaluate ...` 则加载策略、执行新评测，写入独立的发布运行目录。不能运行一次报告脚本就宣称完成了重训或新评测。

```bash
python report.py
```

已有本机产物齐全时，输出应包括 GRPO / IGPO / VCR 的 test EM：56.25%、52.54%、56.84%。缺少产物时失败是正确行为；不能用 Markdown 表格倒填成“新运行结果”。

## 分母必须完整

假设三组模型都只跑完前 20 道容易题，它们的 ID 集相同，但不代表正式 512 题比较已经完成。当前比较入口检查冻结题集、完成摘要、预测哈希与协议，而不只检查两个模型的题目集合相同。

遇到 malformed call、截断或错误答案要保留任务。不能删除失败样本之后再算平均，也不能因为一组的证据完整率为零，就让打印结果崩溃或省略该组。

## 三个容易混淆的比较

| 比较 | 能回答什么 | 不能直接回答什么 |
|---|---|---|
| Base→SFT，同一 Agent 模式 | 微调后整个任务行为改变多少 | 纯知识或纯推理能力变化 |
| Base→SFT，完全相同静态材料 | 排除检索策略变化后答题表现如何 | 自主检索是否变好 |
| 同 SFT 起点的 GRPO→VCR | 增加声明信号后的差异 | SFT 数据增强本身贡献多少 |

当前相关性推理 SFT 尚缺完整 test 单独评测，所以不能用原教师 SFT 的 test 分数替代它，计算“VCR RL 带来的全部提升”。

## 看差值，也看不确定性

VCR 相对同起点 GRPO 的 test EM 差是 +0.59pp，区间包含零；提前停止率差为 −10.94pp，区间不包含零。二者应该分别描述。当前 VCR 的 F1 更低，不能只列 EM 最大值。

配对 bootstrap 把同一问题在两个模型上的差值一起重采样，减少问题难度差异的干扰，但它没有重新训练模型。因此，它不估计训练种子方差，也不能修复长期反复查看 test 带来的研究选择偏差。

## 最后的自检

如果训练 loss 降低、参数移动、平均 reward 增加，但留出集上的答案和证据都没有改善，应该怎样报告？答案是保留训练执行证据，同时报告没有观察到任务收益；不能把参数移动或中间代理信号改写成正结果。
