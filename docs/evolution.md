# 从“奖励引用”到“检查证据判断”：EviSearch-RL 的完整演化故事

这个项目最初想回答一个看起来很直接的问题：给一个会搜索的小模型增加证据奖励，它是否就能更可靠地完成多跳问答？第一轮实验能跑通，证据奖励也有一个更高的分数。但继续检查后发现，模型首先学会的可能只是输出合法 JSON；写进奖励公式的证据项，在多数采样组里甚至没有改变相对优势。

后面的工作并不是沿着一个正确想法不断优化。我们扩大数据，重做工具环境，采集教师轨迹，对比六种 RL 配方；又检查过程奖励、采样多样性、完美轨迹重训、优化超参、停止信用、在线蒸馏和错误恢复。几次看似合理的诊断被下一轮实验推翻：更多有差异的采样组没有明显提高分数，更大的教师让学生更早停止，强制多读文档反而让 EM 下降了 10.74 个百分点。

最后留下的线索来自数据本身：原来的成功示范几乎不读错文档，5,093 个工具调用轮没有一句解释。学生必须隐式完成“这篇文档回答哪一跳”的判断，却几乎没有学过如何识别干扰。把判断写出来后，错误第一次变得可直接检查；这才有了当前的相关性推理示范与可验证声明奖励（VCR）。

**目前最清楚的结果是行为变化，不是已经确立的答案准确率突破。** 同一起点上，VCR 的 test EM 为 56.84%，普通 GRPO 为 56.25%，差值区间包含零；提前停止率则从 28.12% 降到 17.19%，配对区间不含零。扩展到 Qwen3.5-9B 后，加性 VCR 损失了证据完整率；改成保号、有界的乘性形式后，test EM 68.95% 第一次超过同起点 GRPO 的 66.99%，但区间含零、dev2 方向相反，稳定的仍是提前停止下降。本文保留通向这个结果的数字、失败、判断反转和证据边界，不把历史改写成一条必然成功的路线。

全文 EM、F1 和行为率通常以百分数表示，差值用百分点（pp）；奖励值、相关系数不乘 100。区间沿用各阶段的同题或分组 bootstrap 95% 区间，**只描述给定模型下的问题抽样不确定性，不包含训练种子波动**。早期医学统计还按查询分组，不能把 64 道题都当作独立查询。

“证据完整”在主任务中指取齐标注支持文档，不是证明每句话都成立；“完整证据时 EM”只在该模型取齐证据的题上计算，不同模型的分母会变。提前停止通常指证据不完整、仍有搜索预算却已作答；历史失败分类还会先筛选答错题，后文会区分这两种计数。

主任务是固定候选语料里的 MuSiQue 多跳问答，不是开放互联网检索。MedHop 曾是重要探索方向，后来成为辅助诊断；其药物—蛋白质实体共现链始终只是证据代理，**不是医学蕴含、临床有效性或因果关系验证**。

## 1. v1：跑通闭环以后，首先遇到的是归因问题

### 1.1 起点：一个模型、真实工具、两个奖励

最初选择 Qwen3.5-2B，BF16、LoRA rank 8 / alpha 16、seed 42。规模足够小，能在共享 GPU 上真实执行 SFT、在线采样、GRPO 和独立重载评测；也足够暴露小模型在多跳工具任务中的困难。

工具必须真正被调用。模型输出搜索标签却没有得到真实 observation，不算完成 agent 训练；提示和工具返回也不能作为 assistant 的监督目标。两个 RL 分支从完全相同的 SFT adapter 出发，使用同一任务顺序，各完成 128 次更新、512 条真实采样轨迹。

```text
答案奖励 = 合法 JSON × 答案 EM
证据奖励 = 合法 JSON × 答案 EM × (0.7 + 0.3 × 引用 F1)
```

这借鉴了检索 RL 与证据奖励的思路，但不是 ReSearch 或 CaRR 的完整复现。后来核对原实现，发现 ReSearch 的原奖励使用答案 token F1、有效零 F1 的特殊分数及标签检查；CaRR 的实体识别、蕴含和连通性验证器也没有在这里复现。这个更正不改变已有数字，却改变了能对外声称什么。

### 1.2 一个好看的总分，可能主要来自学会格式

| 模型 | 通用 EM（64 题） | 通用引用 F1 | 医学 EM（64 题） | 医学引用 F1 |
|---|---:|---:|---:|---:|
| 未微调 Base | 0.00% | 0.0% | 0.00% | 0.0% |
| SFT | 37.50% | 57.4% | 7.81% | 7.3% |
| 答案奖励 RL | 32.81% | 53.9% | 6.25% | 5.4% |
| 证据奖励 RL | 40.62% | 60.5% | 6.25% | 5.7% |

如果只看 Base→SFT 的通用 EM 从 0 到 37.5%，很容易把它写成推理能力大幅提升。但评测必须先解析指定 JSON；Base 的最终 JSON 合规率就是 0。把协议、工具和材料利用拆开，故事变了：

| 同一 Agent 模式下的指标 | 通用 Base→SFT | 医学 Base→SFT |
|---|---:|---:|
| JSON 合规率 | 0.00% → 98.44% | 0.00% → 100.00% |
| 出现无效工具调用的题目比例 | 48.44% → 1.56% | 56.25% → 0.00% |
| 检索支持覆盖 / 医学路径代理 | 63.28% → 63.80% | 3.12% → 7.81% |

通用检索覆盖几乎没变，最明确的改善是协议与工具控制。为减少检索策略干扰，又补做了相同静态材料下的 Base/SFT 对照，两者逐题收到同一输入：

| 固定材料答题 | Base EM | SFT EM | 差值及 95% 区间 |
|---|---:|---:|---|
| 通用 | 7.81% | 9.38% | +1.56 pp [−4.69, +7.81] |
| 医学 | 12.50% | 6.25% | −6.25 pp [−15.38, +2.78] |

这没有建立固定材料答题能力的提升。静态对照是在看过原始结果后追加的诊断，也不是独立新测试。此后项目保留了 Base、Agent 和 static 三条参照，避免把格式改善全部算成知识或推理收益。

### 1.3 奖励公式变了，但 64.8% 的组没有任务相对信号

GRPO 比较的是同题多条轨迹之间的相对奖励。四条都错、四条都对且分数相同，组内就没有任务优势。两臂各 128 组里，只有 45 组有任务优势，零方差组都占 64.8%；引用项真正改变优势的组，在两份采样上分别只有 14 和 13 组。

原因可以用一个小例子理解：若只有一条答对，其奖励从 1 改成 0.8，而其余三条仍为 0，经组内标准化，优势几乎不变。若几条答对轨迹引用分相同，也没有新的区分方向。**把证据项放进公式，不等于提供了新的学习信号。**

医学更弱：44 个医学训练组里，两臂分别只有 5 和 4 组有任务优势，引用项仅改变 1 和 0 组。测试中还有 9/64 题，即使查看全部候选摘要，也无法形成当前定义的两三篇文档共现路径。这是任务代理与语料条件的限制，不能靠训练损失下降掩盖。

证据奖励相对答案奖励的通用 EM 差为 +7.81 pp，区间 [1.56, 15.62]；但相对 SFT 只有 +3.12 pp，区间 [−4.69, 12.50]。“优于这次答案奖励对照”与“稳定优于 SFT”是两件事。医学 EM 没有收益。

这一轮 SFT 用了 250 次更新、9.7 分钟，两个 RL 分支分别 21.7、21.5 分钟。它建立了可运行闭环，也明确了下一步需要扩大问题规模、检查优势，而不是继续围绕一个小测试集最高分讲故事。

## 2. v2：扩大实验，分清过程反馈究竟增加了什么

### 2.1 从两个奖励扩展到可解释的对照阶梯

第二阶段冻结 6,000 条混合 SFT、1,024 道 RL 题、128 道 dev 和新的 512 道主测试题。常规 RL 每题采样 4 条，一共 4,096 条轨迹；每组复用两次优化，共 2,048 次更新。后一次更新使用保存的旧策略概率，重要性比率才会实际变化。

| 对照 | 新增信号 | 要排查的因素 |
|---|---|---|
| GRPO | 只有终局奖励 | 基线 |
| Prob + Joint | 金标答案几何均值概率的逐轮变化，与终局联合归一化 | 过程反馈本身有没有帮助 |
| Prob + Separate | 相同概率变化，过程与终局分别归一化 | 两类奖励的尺度是否互相干扰 |
| IGPO | 改用平均对数概率的逐轮变化，分别归一化 | 对数尺度是否改善信号 |
| DAPO | 动态采样等对应优化设置 | 增加有效对比组是否有收益 |
| GSPO | 序列级重要性比率等对应设置 | 换优化方式是否更稳定 |

这些臂都独立从同一个 SFT 起步，不是在上一个方法的权重上继续训练。金标答案只在无梯度的 teacher-forcing 评分中出现，不进入实际 rollout 的提示或工具观察。

v2 统一采用训练口径的答案 token-set F1 和格式惩罚，而非 v1 的 EM 奖励。边界测试发现：答对却没有检索、或者引用伪造 ID，在当时评分下仍可能得到 1；重复词也会被 set F1 消去。这些是评分函数的真实边界，不能直接等同于模型已经学会利用漏洞，但必须保留审计，不能继续套用 v1 的证据约束描述。

### 2.2 一次实现细节，足以伪装成算法差异

GPU 探测发现，所用 TRL 的 chunked log-prob 路径忽略了 `batch_size`：旧策略和参考策略按四条一起评分，训练却按单条执行。BF16 下，两种计算形状的舍入差异已经能让 GSPO 在新轨迹**第一次更新之前**出现 25% 的裁剪。

此时策略还没更新，裁剪不应被解释为“策略变化太快”。统一为单条评分后，同条件下更新前裁剪率和初始 KL 都回到 0。修正应用于所有分支，早期探测单独归档，不混入正式结果。这是后来坚持记录 dtype、mask、旧概率与恢复边界的原因：它们会改变实验含义。

### 2.3 普通 GRPO 有收益，过程奖励尚未显示额外收益

| v2 主测试，512 题 | EM | F1 |
|---|---:|---:|
| Base，Agent | 0.00% | 0.00% |
| SFT，Agent | 40.23% | 48.65% |
| GRPO | 45.70% | 53.82% |
| Prob + Joint | 43.75% | 51.52% |
| Prob + Separate | 43.16% | 52.06% |
| IGPO | 43.36% | 52.02% |
| DAPO | 44.14% | 54.56% |
| GSPO | 48.24% | 56.70% |

GRPO−SFT 为 +5.47 pp [2.15, 8.79]。GSPO 数值最高，但相对 GRPO 的 +2.54 pp 区间为 [−1.17, 6.25]；IGPO−GRPO 为 −2.34 pp [−6.45, 1.56]。这些结果支持继续使用 GRPO 作为基线，没有确立过程奖励或 GSPO 的稳定优势。

Base/SFT 在完全相同静态材料下的 EM 为 8.98%/14.06%，与 Agent 的 0.00%/40.23% 分开报告。DAPO 为凑齐有效组生成了 8,964 条轨迹，而常规臂为 4,096 条，不能称为相同采样成本。共享机器上 DAPO 记录 115.9 分钟、GRPO 181.7 分钟，也不能据此给算法排纯速度榜。

另一个问题变得更突出：搜索结果里出现过一个文档 ID，并不表示模型读到了需要的那段原文，更不表示它主动选出了证据。要继续研究检索行为，环境本身需要先变得可观察。

## 3. v3：拆开搜索、阅读、保存，也重新审视教师数据

### 3.1 把“证据从哪里来”变成明确状态

新环境把交互分成三件事：`search` 发现候选，`read` 返回原文，`add_evidence` 保存已读片段。最终答案只能引用已保存证据；保存保留来源和字符位置，重复保存幂等，工具观察持续显示剩余预算。

最终生产协议是 3 次搜索、Top-5、32 词预览，8 次阅读、每页 400 词，8 次保存、容量 8 条；稳定短句柄 `d1`、`d2` 不随排名变化，内部仍可追溯原始 ID。SFT 完整序列上限为 8,192 tokens，RL/评测每回合最多生成 512 tokens，轨迹追加内容预算为 6,144 tokens。

奖励也进一步与证据状态对齐：训练答案 token-set F1 乘证据 F1；截断、非法工具行为、格式或引用错误受到惩罚。这使 v3 与 v2 的差异同时包含环境、数据和奖励，不能把成绩变化全部归功于某个 RL 算法。

### 3.2 64 题教师试生成：22 条通用合格，医学一条也没有

第一次官方教师盲生成选择 48 道通用、16 道医学题，每题最多尝试三次。最终 157 条尝试只收录 22 条通用示范，医学 0/16。1,081 次 API 请求全部 HTTP 200，总用量 4,415,065 tokens；不是网络错误导致的失败。

逐条使用冻结源码重放，157/157 条工具返回和评分完全一致。接下来的调查必须从任务定义和工具链入手，不能停在“强教师也不行”。

首先，4 道医学种子的完整候选语料最短需要 4 篇文档才能连接，而校验器只接受 2–3 篇。它们不是原数据无解，而是训练种子选择与当前评分定义不匹配。这四题已经消耗 12 条尝试、118 次请求、718,821 tokens。

其次，医学部分 144 次成功搜索中，包含 UniProt 蛋白质 ID 的查询为 0。教师反复围绕药物名搜索，没有利用已读到的中间蛋白实体继续桥接。泛泛要求“跟随中间实体”，不足以教会这套特殊 ID 体系下的检索策略。

再沿证据链逐层检查 48 条医学尝试：

| 检查位置 | 能形成当前定义路径的尝试数 |
|---|---:|
| 完整候选语料 | 36/48 |
| 搜索返回过的文档，离线查看全文 | 9/48 |
| 打开过的文档，离线查看全文 | 5/48 |
| 实际返回给教师的阅读片段 | 1/48 |
| 实际保存的片段 | 0/48 |
| 最终引用的片段 | 0/48 |

前几行的全文是离线检查材料，不代表教师已经看见。旧阅读页长只有 160 词，而医学摘要中位数 259 词，401/430 个文档出现次数超过一页；通用材料中位数只有 71 词。同一预算对两类任务施加了很不同的限制。

一个具体例子是 `MH_train_1439`：教师答对了 `DB00945`，也读到了连接 `DB00461 → P35354 → P23219 → DB00945` 的三个片段，却漏存含 `P35354、P23219` 的中间文档。EM=1，证据 F1=0；轨迹还含三次越限调用。事后用已知标签人工选择文档，在 3 Search + 5 Read + 3 AddEvidence 内能通过，只证明工具预算内存在可行路径，不是教师成功样本，更不能计入通过率。

最后，44/48 条医学尝试发生搜索或阅读预算耗尽；25 条被输出上限截断，其中 23 条先出现预算错误。首次预算错误后又消耗 179 次请求、1,734,240 tokens。把输出上限继续调大并不能解决前面的路径、分页和收尾问题。

通用题也不是只有模型知识问题：48 题里有 30 题曾答对，27 题曾同时答对且证据完整，再要求零非法调用后剩 22 题。严格 EM 还拒绝了 `Qu Neng` 对 `Ming general Qu Neng` 这类表达差异。是否补别名需要独立审核，不能通过修改冻结测试的答案口径制造提高。

### 3.3 生产数据的成功，带着一个后来才看清的代价

后续先筛选对校验器可行的训练种子，再改进医学任务说明、阅读页长、预算可见性和错误后的收尾。生产阶段还做了一个明确选择：教师可以参考训练题答案与支持文档，生成有标注条件的工具示范；学生编码前去掉教师专用信息，工具仍必须真实执行并可在普通 actor 提示下回放。

这提高了构建可靠性，却改变了数据性质。收录率不再是教师自主解题准确率；即使特权提示被移除，教师利用标签选择动作所造成的轨迹分布偏差仍会留下。后来“示范过于顺利”的问题，就来自这里。

最终 manifest 汇总 51 次来源运行、2,483 题次、4,495 条候选轨迹，批次内合格 1,805 条，去重和配额选择后收录 1,800 条。对应 23,034 次 API 请求、81,487,782 个 API tokens，无缺失用量请求。这个口径只覆盖 manifest 中的来源目录，**不含早期盲生成等其他实验，也不是整个项目账单**。

| SFT 类型 | 对话数 | assistant 监督 tokens | 监督 token 占比 |
|---|---:|---:|---:|
| 通用 Agent | 1,320 | 378,690 | 27.95% |
| 医学 Agent | 480 | 199,707 | 14.74% |
| 单工具 | 600 | 91,916 | 6.78% |
| 通用对话 | 1,800 | 357,313 | 26.37% |
| 长文档 | 600 | 89,642 | 6.62% |
| 安全 | 300 | 22,087 | 1.63% |
| 代码 | 900 | 215,755 | 15.92% |
| 合计 | 6,000 | 1,355,110 | 100%（舍入前） |

原始来源为 MuSiQue 2,320 条、MedHop 480 条、No Robots 2,300 条、Magicoder 600 条、SafeRLHF 300 条；来源分类与训练用途分类不同，不能逐行等同。检索/阅读样本包含 2,566 道不同父题，最长完整序列 7,895 tokens。1,800 条教师示范全部执行回放，提示与工具 observation 的 loss mask 为零；不能把对话占比当作模型实际接收的监督 token 占比。

### 3.4 在新环境里，GRPO 的收益更清楚，过程奖励的问题也更清楚

| v3 主测试，512 题 | EM | F1 | 带证据成功率 | 平均工具调用 |
|---|---:|---:|---:|---:|
| Base | 6.25% | 6.72% | 1.17% | 15.93 |
| SFT | 43.75% | 52.60% | 35.55% | 5.99 |
| GRPO | 53.91% | 63.55% | 43.75% | 6.74 |
| Prob + Joint | 44.14% | 55.03% | 33.40% | 6.98 |
| Prob + Separate | 53.52% | 63.68% | 44.53% | 6.63 |
| IGPO | 52.93% | 62.74% | 42.77% | 6.73 |
| DAPO | 54.49% | 64.29% | 45.31% | 6.66 |
| GSPO | 54.30% | 63.92% | 44.53% | 6.71 |

GRPO−SFT 为 +10.16 pp [6.25, 14.06]。联合归一化的 Prob + Joint 比 GRPO 低 9.77 pp [−13.67, −5.66]；把过程与终局分开归一化后，相对 Joint 回升 9.38 pp [4.88, 13.87]。但从 Separate 改为对数概率 IGPO 又没有获得额外改善：−0.59 pp [−4.49, 3.12]。

DAPO、GSPO 相对 GRPO 分别只有 +0.59 pp [−2.93, 4.10]、+0.39 pp [−3.32, 4.10]。不能把小数点排序写成可靠的方法排名。

仍保留 Base 对照：Agent 格式合规率 12.30%→100%，而相同静态材料下 EM 13.67%→18.95%，差值 +5.27 pp [2.54, 8.20]；512 题输入消息逐题相同。SFT 确有固定材料表现变化，但 Agent 上 37.5 个百分点的总差仍不能全部解释成推理变化。

医学辅助集还给出一个反例：Base 不调用工具就有 15.62% EM，带证据成功率却为 0；GRPO EM 为 26.56%，带证据成功率也只有 3.12%。能猜中答案与完成可追溯证据任务，始终不是一回事。

### 3.5 训练成本、共享显存与恢复，不应从故事里消失

SFT 750 次更新用时 35.7 分钟。各 RL 臂都是 2,048 次更新，但真实生成量与成本不同：

| 方法 | 留存路径中的实际轨迹 | 生成 tokens | 正式尝试训练分钟 | 额外 IG 评分秒数 |
|---|---:|---:|---:|---:|
| GRPO | 4,096 | 1,118,917 | 344.1 | 0 |
| Prob + Joint | 4,096 | 1,117,523 | 434.8 | 2,249.4 |
| Prob + Separate | 4,096 | 1,137,043 | 368.5 | 1,972.3 |
| IGPO | 4,096 | 1,119,659 | 393.7 | 2,194.6 |
| DAPO | 9,324 | 2,581,198 | 776.5 | 0 |
| GSPO | 4,096 | 1,140,935 | 430.9 | 0 |

额外评分约占 IGPO 记录时间的 9%，不能凭有一次额外前向就说耗时翻倍。上表也不是全部开销：一次 Prob + Joint 失败尝试已消耗 1,078 次更新、2,160 条轨迹、190.1 分钟；GSPO 另有两次短失败尝试。正式尝试内部也有暂停与回退，DAPO、GSPO、Joint、Separate 分别留下 7、8、7、2 次暂停记录。正式尝试耗时已经累计内部暂停段，不能把回退时间再加一遍；留存轨迹之外的重生成量则需另计。

一个恢复缺陷尤其重要：一组轨迹有两次更新，奇数步暂停不在完整复用边界；原生 checkpoint 轮换却删掉了唯一可恢复的偶数步检查点。修复后先归档奇数步或缺状态检查点，保留完整边界，再验证 optimizer、scheduler、RNG、题序、reference 和轨迹前缀。真实恢复中重生成的 16 条轨迹曾有 15 条一致，也曾跨 GPU 只有 8 条一致，因此只声称恢复了保存状态和流程，不声称与未中断训练逐位等价。

还有精度核验：原 SFT adapter 是 FP32，冻结 reference 以 BF16 保存，PEFT 恢复时又可能把存储类型提升为 FP32。正确比较是参考数值是否仍等于当初的 BF16 快照，不能拿原始 FP32 SFT 逐值比较后误报 reference 漂移。

资源保护同样要诚实记录。项目要求留出 6 GiB，但共享 GPU 曾测到 386 MiB 空闲，另有 DAPO 步间独立读数 5,703 MiB。进程自身 allocator 上限和步末暂停检查，不保证其他进程不会让空闲显存跌破保护线。后续成功日志不能抹掉这些事件。

v4 对这批源运行的完整审计计入失败和回滚重做后，得到 **33,412 条实际轨迹、9,214,249 个生成 tokens、13,941 次实际更新、49.04 小时训练段时间**。它不含 SFT、教师、probe、评测，也不是 v1–v5 全项目总耗时。记录这些开销，是为了让“多采样是否值得”有可核对的分母。

## 4. v3 诊断：停止增加算法，先检查信号到底在做什么

### 4.1 检索更全，与利用证据答对，开始分离

| test 512 题 | 证据完整率 | 证据完整时 EM | 证据不全时 EM |
|---|---:|---:|---:|
| SFT | 51.95% | 68.80% | 16.67% |
| GRPO | 64.84% | 70.48% | 23.33% |
| Prob + Joint | 57.42% | 65.31% | 15.60% |
| Prob + Separate | 64.84% | 71.08% | 21.11% |
| IGPO | 67.77% | 66.57% | 24.24% |
| DAPO | 64.45% | 71.21% | 24.18% |
| GSPO | 66.60% | 68.62% | 25.73% |

SFT→GRPO 最明显的变化是完整率从约 52% 到 65%；完整证据时 EM 仅从 68.8% 到 70.5%。IGPO 则表现为完整率更高、完整证据时 EM 更低。后一个条件指标的题目集合随模型变化，这不是“同一批完整证据题上推理能力下降”的因果证明，但足以提示：检索进度与最后答对不是同一个目标。

按同题转移看，SFT→GRPO 有 83 题由错变对、31 题由对变错，205 题始终错、193 题始终对。只对答错题作互斥分类：

| 失败类型 | SFT | GRPO |
|---|---:|---:|
| 缺证据、尚有搜索预算就停止 | 186 | 95 |
| 缺证据、搜索预算已用满 | 18 | 43 |
| 证据完整但答错 | 83 | 98 |
| 非法或截断 | 1 | 0 |

这里的 95 是“答错且提前停止”的题数，不等于后来覆盖所有预测的提前停止率分子。完整证据却答错的样本中，SFT 有 45/83、GRPO 有 50/98 的 F1 就是 0，不能把全部失败解释成严格 EM 的表面形式问题。

六个 RL 方法至少一个答对的题占 72.7%，全部答对的占 27.7%；140/512 题没有任何方法答对。不同策略有互补性，但这不是一个实际集成系统的成绩，也不能拿 oracle 并集与单模型直接比较。

### 4.2 IG 确实识别了检索进展，却没有同样强地识别最终成功

对 IGPO 的 1,024 组、4,096 条训练轨迹，离线核对前缀评分与最终回报：

| 诊断量 | 实测 |
|---|---:|
| 累计 IG 与组内去均值终局奖励的 Spearman | 0.17 |
| 累计 IG 与证据覆盖率，终局有差异的 1,764 条轨迹 | 0.62 |
| 同上，终局恒定但覆盖有差异的 148 条轨迹 | 0.44 |
| 失败调用轮次 | 411 |
| 失败轮 IG 均值 / 正值比例 | +0.04 / 50% |
| 失败轮最终仍获正优势 | 47/411 |
| 重复调用轮次 / IG 均值 | 398 / −0.08 |

因此，早期“IG 只奖励搜索，不关注证据质量”的说法需要修正：它确实跟随证据收集。进一步对支持文档与干扰文档分组，读支持文档 3,023 轮平均 IG 为 +0.455，读干扰文档 783 轮为 −0.399，正值比例分别 69% 和 29%。它不是完全失效的信号。

问题在于，它衡量的是“给定金标答案后，这段前缀让答案更可能了吗”，而策略要完成的是“我能否自己生成正确答案”。两者不等价。单独保存证据没有带来新文本，IG 也可能接近零；这不代表保存动作没有任务价值。

另一个容易误读的量是：归一化后，过程项占逐轮即时奖励平方和的 87.2%。这不能推出“梯度由过程奖励主导”，因为终局奖励会在回传时加入每一轮，还要经过优势、mask 与策略比率。必须继续检查真正进入损失的优势。

### 4.3 为什么把失败轮即时奖励置零，仍然不能消除正优势

把同一批固定轨迹拿来反事实重算，结果是：

| 优势规则 | 失败调用轮次获正优势的数量 |
|---|---:|
| 原 IGPO | 47/411 |
| 只把失败轮即时过程信号门控掉 | 22 |
| 过程权重降为 0.3 | 14 |
| 过程权重降为 0.1 | 11 |
| 失败门控 + 权重 0.3 | 7 |
| 只在终局恒定组启用过程信号 | 11 |
| 失败门控 + 只在恒定组启用 | 5 |
| 仅终局奖励 | 0 |

后续回报仍会向前累加，所以失败轮自己的即时项为零，并不保证该轮最终优势非正。原 IGPO 有 20.1% 的优势质量落在终局恒定组、8.2% 在有终局差异的组里与终局方向相反；轨迹优势与终局奖励的相关仍高达 0.855。它更像在总体跟随终局的信号上加了一项扰动，不能由即时奖励占比推断完整更新方向。

359 个终局恒定组里，210 组四条全部满分，111 组全部零分，其中只有 34 组的证据覆盖率有差异。为这些少数组继续增加复杂门控，未必是下一轮最值得花训练预算的方向。重放只验证信号算术；换规则后策略和采样都会变化，不能把这张表当作新模型成绩预测。

### 4.4 pass@k：GRPO 提高了常见成功率，没有扩大这次观察到的成功覆盖

为了区分“从来不会”与“会但概率低”，在 dev 128 题上用 temperature=1、top_p=0.95 采样。每题先取 4 条，只对前四条全错的题补到 16 条；SFT 共 1,028 条，GRPO 共 1,052 条。这里的 pass@k 是本次样本前 k 次中至少成功一次的题目比例，不是 greedy，也不是模型理论上限。

| k | SFT pass@k | GRPO pass@k |
|---|---:|---:|
| 1 | 39.1% | 51.6% |
| 2 | 56.3% | 59.4% |
| 4 | 66.4% | 64.8% |
| 8 | 72.7% | 73.4% |
| 16 | 78.1% | 78.1% |

前四条平均 EM 从 41.4% 提高到 52.5%；四条全对的题从 23 增到 52，混合对错从 62 减到 31，四条全错从 43 到 45。GRPO 把一部分会的题做得更稳定，却没有在这次有限采样里扩大 pass@16 的覆盖。

两者各有 28 题 16 次都没答对。其中从未取齐证据的题由 SFT 的 9 道减为 GRPO 的 2 道，曾取齐却始终答错的由 19 道增为 26 道。检索改进没有自动解决最后的推理与答案表达。

人工浏览还看到 `Sir Geoffrey Boleyn` / `Geoffrey Boleyn`、`King James I` / `King James I of England`、`North Pole` / `latitude 90° North` 等表达差异；SFT 那 19 道题里有 8 道 best F1 ≥ 0.75。但这不是正式的金标审计，不能直接宣布它们都应算对，更不能修改测试 EM 来抬分。

### 4.5 一个被推翻的建议：把每题采样从 4 条扩大到 16 条

看到很多全错组，自然会想增加每题采样量。但固定 4,096 条轨迹预算下，更多样本意味着更少问题组。用现有采样池模拟后的估计是：

| 采样方案 | 每组平均条数 | 有对错对比的概率 | 可覆盖组数 | 预计有对错对比的组数 |
|---|---:|---:|---:|---:|
| 固定 2 条 | 2.00 | 0.261 | 2,048 | 534 |
| 固定 4 条 | 4.00 | 0.427 | 1,024 | 437 |
| 固定 8 条 | 8.00 | 0.514 | 512 | 263 |
| 固定 16 条 | 16.00 | 0.556 | 256 | 142 |
| 先 2，必要时补到 4 | 3.46 | 0.426 | 1,183 | 504 |
| 先 2，必要时补到 8 | 5.59 | 0.520 | 732 | 381 |
| 先 4，必要时补到 16 | 10.07 | 0.555 | 407 | 226 |

它是静态采样池上的 bootstrap 模拟，不是新训练；前四条已成功的问题没有继续采样，也限制了可估计的多样性。但它足以推翻“增大 k 必然产生更多有效学习组”的直觉。

真实 DAPO 又给了第二层证据：它把有终局差异的更新从 GRPO 的 1,162 次提高到 2,048 次，约多 76%，生成 token 约 2.3 倍，test EM 却只多 0.59 pp，区间跨零。**有效信号的数量不再足以解释瓶颈。**

这也解释了为什么参数变化不是学习证明：GRPO 的 443 个终局恒定组仍可有 KL 梯度。只看每组采样后的第一次更新，恒定组梯度范数中位数约 0.0071，有差异组约 0.4898，相差约 69 倍；对应约 886/2,048 次更新没有任务相对优势。IGPO 在恒定组中的梯度更大，也没有因此获得更高测试分。

接下来有两条更可检验的路：既然多个策略已经找到不少完美轨迹，直接监督它们是否有用；或者当前 RL 的更新配置是否过于保守。这就是 v4。

## 5. v4：完美轨迹重训、超参扫描，以及新种子带来的降温

### 5.1 先冻结新的开发集，避免在旧 test 上继续选方法

dev2 新增 512 题，排除 RL、SFT 父题和旧评测中的 ID、规范化问题与分解组件。二跳/三跳为 394/118；候选池只有 4 道特定三跳子类型，实际抽到 2 道，因此子类型结构不与旧 test 完全一致。

原 GRPO 在 dev2 上 58.79%，旧 test 上 53.91%，差 4.88 pp，落在预先声明的 5 pp 难度门控内。这个门控不是证明两个集等价；它只是允许按方案继续，也不允许反复重抽到想要的分数。

### 5.2 RAFT：已经找到成功轨迹，为什么再教一遍仍没有提高

六个策略在 800/1,024 道训练题上至少产生过一次完美轨迹，共 12,761 条完美轨迹，已解题的中位数为 17 条。这使“缺少任何成功样本”不再是足够的解释。

RAFT 从源轨迹中筛选并重建 800 题、1,519 条通过回放与 mask 校验的对话。源池包含六个策略的 29,804 条留存轨迹，其中 accepted 为 24,576 条，DAPO 的额外采样也在其中；这不是与一轮 GRPO 等成本的数据获取方式。

结果：RAFT dev2 EM 58.59%，GRPO 58.79%，差 −0.20 pp [−3.32, 2.93]，未通过预设的 +5 pp 门控。它不能证明所有成功轨迹再训练都无效，但本次“把已经找到的完美轨迹再监督”没有解决瓶颈。

### 5.3 短训练不能代表全长，所以扫描还是跑了完整预算

为节省后续扫描成本，先检验 512 次更新能否复现 GRPO 与 Prob + Joint 的差距。短程 dev2 分别为 56.84%、56.25%，差 +0.59 pp [−2.93, 3.91]，没有重现全长里明显的分离。因此后续不能用短程排序替代全长结论。

| 全长 dev2 对照 | EM | 相对旧 GRPO |
|---|---:|---|
| 旧 GRPO，lr=1e−5 | 58.79% | 基线 |
| beta=0，移除 KL loss | 58.59% | −0.20 pp [−3.91, +3.52] |
| lr=3e−5 | 62.30% | +3.52 pp [+0.20, +7.03] |
| LoRA rank=32 | 61.91% | +3.12 pp [−0.78, +7.03] |

rank=32 分支也重新做了 SFT，其 SFT dev2 为 57.62%，旧 rank=8 SFT 为 54.49%；不能把不同起点的差异全部归给 RL 容量。更大参数位移也不是效果保证：lr=3e−5 的 L2 位移明显更大，仍需独立确认。

协议中还发生过一次需保留的更正：实现曾把 RAFT 的 +5 pp 门槛错误套到超参选型上。在任何适配模型 dev2 分数产生前，规则改回“选择超过同长度基线的最佳配置，做两个新种子确认”，RAFT 的门槛没有变。它不是看到结果后降低门槛。

### 5.4 最有希望的学习率，没有在两个新种子上形成稳定收益

| 种子 | 原 GRPO test EM | lr=3e−5 test EM | 同种子差值 |
|---|---:|---:|---|
| 43 | 52.34% | 53.71% | +1.37 pp [−2.54, +5.08] |
| 44 | 52.34% | 52.34% | 0.00 pp [−4.10, +4.10] |

原 GRPO seed 42 为 53.91%，三个种子的观察范围为 52.34%–53.91%。这不是对真实种子分布的充分估计，但提醒了一个事实：此前许多约一个百分点的方法差异，与实际观察到的训练波动处在同一量级。

因此 v5 回到 lr=1e−5 的 `grpo-42` 作参照，不把 dev2 最高的 lr=3e−5 固化成“更好的基线”。旧 test 已被查看，新种子确认也不能被称作新盲测。

<a id="stage-5a"></a>

## 6. v5 前半段：把检索、答题与停止的信用拆开，仍然不够

这一阶段形成了一个工作习惯：新想法先明确它要改变哪个行为、离线应该出现什么信号、达到什么幅度才值得训练。门控不是统计真理，也可能设计得不完善；但没通过就是没通过。若继续探索，必须记录覆盖理由，不能事后把失败改成成功。

### 6.1 ESA：在“结束检索、开始答题”处切开信用

终局奖励会把整条轨迹绑在一起：检索正确但最后答错，检索动作也可能拿负优势；证据不全但猜对，前面的动作又可能拿正优势。证据状态分段优势（ESA）试图在一个明确边界上解开它们。

在最终答案轮之前的状态 s，用当前策略只重采样最终答案 K=4 次，不允许继续调用工具，令 V(s) 为这些真实终局奖励的均值。检索段使用组内标准化的 V(s)，答题段使用 R−V(s) 的标准化残差；当前这次答案不计入自己的价值基线。失败工具轮另外限制优势不能为正。

它不需要价值网络，也不依赖金标答案似然。直觉是：拿到一套通常能答好的证据，就该鼓励检索；这次答案比这套证据的平均表现更差，就该惩罚答题。

实际用最终 `grpo-42` 策略重放早期训练的 205 组、820 条轨迹；环境和原指标 820/820 一致，但价值估计属于离线近似，不是历史采样时的在线策略。

| ESA 门控 | 预设要求 | 实测 | 判断 |
|---|---:|---:|---|
| 终局恒定组获得新非零优势 | ≥20% | 12.9%（85 个恒定组） | 未过 |
| 检索优势与证据覆盖率相关 | >0 | 0.29 | 通过 |
| 完整证据却答错：检索非负、答题负 | ≥50% | 33.7%（184 条） | 未过 |
| 失败轮最终正优势 | 0 | 0/38 | 通过 |
| 外推 1,024 组额外成本 | ≤3 小时 | 2.37 小时 | 通过 |

ESA 没有进入训练。很多状态会稳定地产生同样错误答案，重采样后 V≈R，残差仍为零，没创造足够的新信号。

复查也发现第三个门控本身不够合理：184 条完整证据错误中，140 条所在组四条都取齐证据，组内标准化天然还会把一部分好检索排到负侧。拆开看，答题优势为负的占 46.2%，检索非负占 69.6%。这限制了对 33.7% 的解释，但没有消除第一项失败，也没有证明这个设计值得直接投入完整训练。

### 6.2 PE-OPD：给同一模型推理链提示，教师并没有变强

配套的特权证据在线自蒸馏（PE-OPD）只在模型已保存全部金标证据时触发。教师与学生是同一套权重，教师额外看到中间跳子问题、子答案，但最后一跳答案省略，并检查中间提示是否泄漏最终答案别名。

期望是让带提示的模型更能识别“学生答到了中间实体，却没有完成最后一跳”。逐 token 信号为截断后的教师与学生对数概率差，只作用在最终答案轮。

| PE-OPD 门控 | 预设要求 | 实测 |
|---|---:|---:|
| 带提示相对无提示 greedy EM | ≥+10 pp | 68.4% 对 72.0%，−3.6 pp |
| 原完整证据错误被教师修正 | ≥30% | 26.3% |
| 答错 token 的平均信号低于答对 | 是 | −0.018 对 −0.011，满足 |

共 507 个触发状态。提示模型有 23 次生成工具调用而非答案，学生只有 3 次；排除两者任一不作答后，484 个共同可比状态里教师 71.7%、学生 72.9%，仍没有优势。信号平均绝对值仅 0.021，按原标定公式得到 λ≈38，也提示它不是预期中的强监督。

按门控，PE-OPD 未训练。这个结果否定的是当前模型、提示和状态上的自蒸馏假设，不是所有推理提示都无效。

### 6.3 CSC：离线“继续更好”，在线却学得更早停止

接下来转向一个更直接的失败：尚有预算、证据不全，却已经作答。反事实停止信用（CSC）重建作答前状态，强制继续一次搜索，再让策略按原预算完成任务，比较“停下”和“继续”的实际奖励。

离线取证据不全、完整各 160 个停止状态，每状态两次续跑：

| 指标 | 证据不全 | 证据完整对照 |
|---|---:|---:|
| 停止平均奖励 | 0.156 | 0.755 |
| 继续平均奖励 | 0.251 | 0.616 |
| 继续−停止 | +0.095 [+0.047, +0.144] | −0.140 [−0.218, −0.067] |
| 停止→继续 EM | 21.3% → 31.9% | 64.4% → 61.6% |
| 续跑后证据完整率 | 27.5% | 97.5% |
| 单次续跑时间 | 2.9 秒 | 2.6 秒 |

方向正确，但不全状态收益要求 ≥0.10，实测 0.095；补齐率要求 ≥30%，实测 27.5%。**门控未通过。** 因两层方向可区分，仍以有记录的探索性覆盖进行训练，不能写成“通过门控后上线”。训练只在作答轮加停止信用，其余沿用旧 GRPO 配置。

| 结果 | dev2：GRPO→CSC | test：GRPO→CSC |
|---|---:|---:|
| EM | 58.79% → 56.45% | 53.91% → 50.98% |
| 提前停止率 | 22.7% → 27.7% | 26.2% → 32.0% |
| 证据完整率 | 67.4% → 64.1% | 64.8% → 60.7% |
| 平均搜索 | 2.24 → 2.13 | 2.20 → 2.10 |

test EM 差 −2.93 pp [−6.64, +0.78]，没有显示改善。更关键的是目标行为方向反了。

训练日志提供了解释：证据完整时，“停下”的平均正信用约 +0.65；证据不全时负信用只有 −0.18，而符合条件的轨迹约 60% 已有完整证据。两个层内方向都对，混起来却对“停下”给了更多净正信号。离线门控只看分层均值，没有检查信号按训练频率混合后的净效应。

### 6.4 更大的教师：会给 token 评分，不等于会更好地执行任务

自蒸馏教师不够强，于是检查同词表 Qwen3.5-4B、9B。分词器逐字节相同，显式关闭 thinking 后，200 条真实轨迹的模板渲染逐 token 一致，使逐 token 蒸馏可操作。

教师门控要求 dev greedy EM ≥58.9%（旧 GRPO 的 53.9% 再加 5 pp）、格式 ≥95%；同时检查 token 信号与终局的组内相关，以及失败调用的信号是否更低。探针使用 dev 128 题，信号评分取 128 组、512 条旧轨迹、140,744 个 assistant tokens。

| 指标 | 未适配 4B | 未适配 9B | 9B 任务 SFT 后 |
|---|---:|---:|---:|
| dev Agent EM | 7.8% | 45.3% | 55.5% |
| 格式合规 | 10.2% | 89.8% | 100% |
| 证据完整率 | 6.3% | 54.7% | 80.5% |
| token 奖励与终局组内 Spearman | 0.237 | 0.291 | 0.277 |
| 失败 / 成功调用 token 奖励均值 | −0.072 / −0.042 | −0.090 / −0.037 | −0.091 / −0.022 |

原始大模型的 token 判断信号有区分度，自主工具协议却不合格。于是用学生同一份 6,000 条数据对 9B 做 rank=8 LoRA SFT，750 步、54 分钟，格式完全修复，EM 从 45.3% 到 55.5%。仍低于 58.9% 门槛，不能改写成教师门控通过。

考虑它比学生 SFT 起点 47.7% 高 7.8 pp，且 token 信号通过，项目记录了第二次探索性覆盖。在线蒸馏使用冻结 9B 对学生采样 token 评分，加入 `λ × clip(log π_T − log π_S_old, ±3)`，λ 按原公式标定为 5.78。2B 学生与 9B 教师分置两张卡。

4.61 小时训练后，test EM 52.34%，旧 GRPO 53.91%，差 −1.56 pp [−5.27, +2.15]；dev2 56.25%，旧 GRPO 58.79%。test 提前停止率从 26.2% 到 32.4%，平均搜索从 2.20 到 2.00。没有检测到收益，数值落在旧 GRPO 三种子观察范围内；这不是等效性证明。

训练梯度范数中位数 3.11，而旧 GRPO 约 0.35，梯度被裁到 1.0，说明蒸馏项影响很强。教师只做过 SFT，平均工具调用 5.71 次，旧 RL 策略约 6.8 次；把学生拉向教师，也可能把已学会的继续搜索拉回去。完整证据时 EM 略升、检索却变差，与这个解释相符，但不是独立隔离每个因素的消融证明。

**教师必须在被蒸馏的行为上更强，模型参数更大、总分更高或 token 评分更准，都不足以单独保证这一点。**

### 6.5 DPD：只蒸馏“继续还是停止”，也先被门控拦住

决策点蒸馏（DPD）只监督每个 assistant 轮的第一个 token：调用工具还是直接输出答案。它避免把所有 token 都拉向教师，希望专门改停止决策。

| 320 个停止状态上的诊断 | SFT 学生 | 旧 GRPO | 9B SFT 教师 |
|---|---:|---:|---:|
| 证据不全时 P(继续) | 0.037 | 0.232 | 0.197 |
| 证据完整时 P(继续) | 0.012 | 0.023 | 0.040 |
| 区分不全/完整的 AUC | 0.749 | 0.805 | 0.823 |
| 区分续跑有益/有害的 AUC | 0.631 | 0.640 | 0.675 |

教师排序能力满足两个 AUC 门槛，但在证据不全状态，P(继续) 比旧 GRPO 低 0.035；要求是高至少 0.10。DPD 没有训练，也没有覆盖门控。这与在线蒸馏失败的方向一致：当前 SFT 教师没有额外更强的继续搜索策略可教给 RL 学生。

### 6.6 单侧 CSC：修好了提前停止，却没换来更多正确答案

双侧 CSC 的净正信用问题可以用一个直接对照检验：只对“证据不全、有搜索余量、续跑确实更好”的作答轮施加负信用，取消完整证据状态的停止奖励。训练时使用金标完整性判断，评测不提供。

单侧 CSC（`csc_neg`）训练 5.82 小时。888 条记录到停止信用的轨迹中，226 条为负、均值 −1.39，其余 662 条为零，没有正值，符合设计。

| 指标 | dev2：GRPO→单侧 CSC | test：GRPO→单侧 CSC |
|---|---:|---:|
| EM | 58.79% → 60.16% | 53.91% → 53.52% |
| 证据完整率 | 67.4% → 70.7% | 64.8% → 66.4% |
| 提前停止率 | 22.7% → 18.0% | 26.2% → 21.9% |
| 平均搜索 | 2.24 → 2.29 | 2.20 → 2.25 |
| 用满三次搜索 | 21.5% → 29.1% | 20.5% → 26.4% |

提前停止差在 dev2 为 −4.69 pp [−7.81, −1.76]，test 为 −4.30 pp [−7.81, −0.78]，通过了预先声明的行为判据，支持对双侧信用不平衡的诊断。

但 test EM 差 −0.39 pp [−3.71, +3.12]，没有可检出的提升；完整证据时 EM 从 70.5% 到 68.8%，非法调用也略增。多搜索带来了更多完整证据，却没有自动转化成答案。这使下一步从“怎样让它继续”转向“继续以后究竟读了什么、理解了什么”。

<a id="stage-5b"></a>

## 7. v5 后半段：从“读错了不会补救”，到“没有学会判断相关性”

### 7.1 先问环境上限，再问示范到底教了什么

在 1,024 道 RL 训练题上，用金标分解子问题、并以金标中间答案替换占位符来查询 BM25，全部支持段落进入各跳 Top-5 的题占 85.4%（二跳 87.5%、三跳 78.6%），Top-10 为 93.4%；只用原问题一次查询则为 26.9%。

这是有特权查询的环境可达性探针，不是可部署策略的分数，也不是无条件严格上限。它说明当前约 65% 的证据完整率与环境能提供的材料之间还有空间，不能把所有失败归因于语料不可达。

回看 1,320 条通用 Agent 示范，全部来自有答案、证据条件的教师构建。其中 97.5% 恰好只读金标文档，零工具错误，没有“读错—识别—放弃—换一篇”的过程。旧 GRPO 训练轨迹中，80.6% 也恰好读取支持段落数那么多篇。

在 dev2 上检查真正读到干扰文档的题：

| 模型 | 读到干扰的题占全部题 | 其中保存干扰文档 | 其中最终取齐证据 | 其中 EM |
|---|---:|---:|---:|---:|
| 原 SFT | 29.5% | 98.7% | 1.3% | 16.6% |
| 旧 GRPO | 29.3% | 100% | 10.0% | 29.3% |
| lr=3e−5 | 25.0% | 100% | 7.8% | 26.6% |
| 单侧 CSC | 31.1% | 100% | 22.0% | 32.7% |
| 9B 教师 OPD | 29.1% | 94.6% | 9.4% | 22.8% |

这时最直观的诊断是：成功示范太干净，学生学成了“读到什么就存什么”。但这个诊断还需要进一步检验；不同模型“读到干扰”的子集也不相同，不能直接把条件率差当作同状态因果效应。

### 7.2 RAD：只插入一次读错经历，没有教会它为什么错

补救增强示范（RAD）按题号哈希选择 631/1,320 条通用示范，在第一次读金标文档前插入一次真实干扰阅读：读最近搜索结果里排名最高、原示范从未读过的非金标文档。之后原动作和最终答案保持，干扰文档不保存，工具观察全部重执行。

插入的错误动作不计 loss，避免直接教模型故意读错；提示与观察也不监督。这样原通用 Agent 的 378,690 个监督 tokens 不变，数据类别和训练配方不变，仍为 750 步 SFT。改变的是模型接下来做正确动作时所处的上下文。

| dev2 指标 | 原 SFT | RAD SFT | 预设要求 |
|---|---:|---:|---|
| 读到干扰后保存 | 98.7% | 94.5% | ≤80%，未过 |
| 读到干扰后取齐证据 | 1.3% | 6.1% | ≥10%，未过 |
| 整体 EM | 54.5% | 53.7% | ≥53.5%，通过 |
| 证据完整率 | 59.8% | 59.2% | 诊断项 |

方向有变化，幅度不够。按规则没有继续训练 `grpo_rad`。重要的不是“增强数据完全没用”，而是仅给一次错误上下文，未提供足够的可迁移判断信号。

更细的重放随后修正了“保存是主要瓶颈”的说法。把不完整预测里每个缺失金标段落按位置归因：

| 缺失原因，dev2 | 原 SFT | 旧 GRPO | 单侧 CSC | RAD SFT |
|---|---:|---:|---:|---:|
| 搜索结果里出现过，但没读 | 37.5% | 49.1% | 50.0% | 34.2% |
| 从未出现在搜索结果里 | 62.5% | 50.9% | 50.0% | 63.2% |
| 已读却没存 | 0% | 0% | 0% | 2.6% |

分母是缺失段落，不是题目。旧 GRPO 约一半缺失证据其实就在候选列表里，阅读预算 8 次通常只用了两三次，却没打开；另一半从未被搜出来。“读错后保存”是明显症状，但多数缺失发生在阅读之前，查询和选择同样关键。

### 7.3 FSR：把训练直接放到失败现场，正样本仍然太少

失败状态重启（FSR）想绕开整条轨迹中很少遇到补救的问题：从“刚读到第一篇非金标文档”的真实状态开始，让 SFT 起点策略采样四条后续。前缀通过真实调用重放恢复，作为提示，不计损失。

旧 GRPO 的训练题中有 518 道存在这种失败状态，离线抽 200 个、每个四条：

| FSR 门控与诊断 | 实测 | 预设要求 |
|---|---:|---|
| 四条中至少一次补齐证据的组 | 15.0% | ≥25%，未过 |
| 组内终局奖励有差异 | 50.5% | ≥40%，通过 |
| 单条续跑耗时 | 3.8 秒 | ≤15 秒，通过 |
| 单条补救率 / EM | 8.0% / 14.8% | 诊断项 |
| 至少一次答对的组 | 29.5% | 诊断项 |
| 非法率 | 7.1% | 诊断项 |

FSR 没有训练。起点策略确实偶尔能补救，但出现频率未达到事先认为值得训练的门槛。不能把 15% 写成“策略完全没有这种行为”，也不能从门控失败证明任何重启训练都无效；这里只能说当前设计的成功采样支持不够。

### 7.4 强制多读一篇：一个很有信息量的负结果

既然缺失金标常在结果列表里、阅读预算也没用满，最直接的替代解释是“它只是读得太少”。但观察性数据不可靠：在 411 个可比较训练组里，多读的轨迹证据完整率低 4.8 pp、EM 低 9.4 pp、奖励低 0.14。可能是已经遇到困难才多读，不能倒推多读导致失败。

于是做了真实干预：在 dev2 的同一 greedy 协议中，每次策略成功打开搜索结果里的文档，环境同轮追加读取该列表排名最高的未读文档，计入原阅读预算；保存和作答仍由模型决定。预设判据是 EM 至少 +3 pp、证据完整率至少 +8 pp，才继续构造广度阅读示范。

| dev2，512 题 | 原 GRPO | 强制多读 | 同题差及 95% 区间 |
|---|---:|---:|---|
| EM | 58.79% | 48.05% | −10.74 pp [−14.45, −7.23] |
| F1 | 66.84% | 57.18% | −9.66 pp [−13.18, −6.38] |
| 证据完整率 | 67.38% | 62.70% | −4.69 pp [−8.59, −0.59] |
| 证据 F1 | 81.9% | 71.2% | −10.66 pp [−12.64, −8.73] |
| 证据完整时 EM | 71.3% | 65.1% | 条件子集不同 |
| 平均阅读次数 | 2.27 | 3.97 | 其中强制阅读 1.98 次 |
| 平均搜索次数 | 2.24 | 1.97 | 搜索反而减少 |

65.6% 的干预题保存了非金标文档。结果与预期相反：给更多材料没有帮助模型选出有用证据，反而增加了干扰。追加阅读对策略是分布外的输入形式，因此这个实验只否定了当前强制追加方案，不能推广为“阅读越多越差”。

它迫使诊断再次前进：缺的可能不是预算或文档数量，而是**相关性判断和从文档中抽取下一跳信息的能力**。补充核对发现，原 1,320 条通用示范的 5,093 个工具调用轮没有一个带解释文字，thinking 也关闭。教师有标签能选对文档，学生却要在纯工具调用中隐式重建全部判断。

### 7.5 ERR：把“这篇文档有何用”写出来，错误才变得可观察

显式相关性推理示范（ERR）建立在 RAD 上，在读取后的下一轮、调用工具之前加入一句短判断，由训练题分解构造：

```text
"{标题}" answers step k ({子问题}): {子答案}.
"{标题}" does not answer step k ({子问题}); try another document.
```

前者说明这篇文档回答哪一跳、得到了什么；后者解释为什么换一篇。前跳占位符替换为相应中间答案，最终答案仍为原 JSON。文字计入 assistant loss，故监督 token 数增加；插入的干扰阅读动作仍不监督。它不是与原 SFT 等 token 的纯格式消融，也不是让评测模型直接看到金标推理链，测试时判断必须由模型自己写。

冻结 manifest 给出了这个变化的实际规模：通用 Agent 监督 tokens 从 378,690 增至 472,974，增加 94,284（约 24.9%）；全体 6,000 条混合数据的监督 tokens 从 1,355,110 增至 1,449,394（约 7.0%）。对话数和各类别配额没有增加，最长完整序列仍为 7,895 tokens。多了多少解释，需要按 token 统计，不能只说“还是同样 6,000 条数据”。

| dev2 指标 | 原 SFT | ERR SFT | 旧 GRPO |
|---|---:|---:|---:|
| EM | 54.49% | 58.01% | 58.79% |
| F1 | 61.1% | 63.7% | 66.8% |
| 证据完整率 | 59.8% | 61.9% | 67.4% |
| 证据完整时 EM | 76.1% | 78.9% | 71.3% |
| 证据不全时 EM | 22.3% | 24.1% | 32.9% |
| 格式合规 | 100% | 100% | 99.8% |
| 读到干扰后保存 / 补救 | 98.7% / 1.3% | 85.7% / 5.0% | 100% / 10.0% |
| 平均生成 tokens | 249 | 312 | 275 |

ERR−原 SFT 的 EM 为 +3.52 pp [0.20, 7.03]，显示了 dev2 上的改善；ERR−旧 GRPO 为 −0.78 pp [−4.49, 3.32]，表示没有检出差异，**不是已经证明二者等效**。

预设门控为 EM≥57.5%、补救≥10%、格式≥98%。EM 和格式通过，补救只有 5%，仍未全过。项目再次记录探索性覆盖，继续 ERR 起点的普通 GRPO。

ERR 还有一个比总分更有用的变化：现在可以直接读出模型的错误判断。dev2 的正面声明中，830 条落在金标文档，225 条落在非金标文档，约 21% 是虚假相关；负面声明只有 46 条，其中 17 条误拒金标、29 条拒绝非金标。600 个写出的中间答案中，70.8% 与金标子答案完全一致。

它开始解释，却仍倾向于把自己选中的文档说成相关。过去只能从最终答案猜它哪里错了，现在能对照训练标注核验一句具体声明。这是 VCR 的直接起点。

## 8. 当前方案：对明确声明给反馈，而不是让似然代理代替判断

### 8.1 先确认 ERR 起点上的普通 GRPO 做到了什么

ERR SFT 之后，使用原有 GRPO 配方，冻结同一个 ERR SFT 作为 reference。为了区分，下文将此臂称为 GRPO-ERR；当前仓库中直接叫 GRPO。

| 指标 | dev2：旧 GRPO→GRPO-ERR | test：旧 GRPO→GRPO-ERR |
|---|---:|---:|
| EM | 58.79% → 62.30% | 53.91% → 56.25% |
| F1 | 66.84% → 69.81% | 63.55% → 66.66% |
| 证据完整率 | 67.4% → 68.8% | 64.8% → 64.3% |
| 证据完整时 EM | 71.3% → 75.6% | 70.5% → 73.9% |
| 提前停止率 | 22.7% → 23.2% | 26.2% → 28.1% |

EM 差在 dev2 为 +3.52 pp [−0.20, 7.23]，test 为 +2.34 pp [−1.56, 6.25]。test 数值超过此前旧 GRPO 三种子的最高 53.91%，但当前只有一个训练种子，配对区间仍含零；跨过一个很小的已观察种子范围，不等于建立了稳定优势。

完整率没有同步提高，条件答对率上升，更符合答题与桥接表现改善的解释，但条件子集不同，不能精确分解因果贡献。ERR SFT 本身还没有完整 test 单独评测，因此不能用旧 SFT 的 43.75% 代替它，计算所谓“当前 RL 净提升”。

补救也没有随普通 GRPO 自动变好：dev2 读到干扰后保存率 96.2%、补救率 2.3%，声明准确率由 ERR SFT 的 62.3% 到 63.2%。单靠终局奖励没有明显修正中间声明。

### 8.2 VCR 的规则：验证文档、跳号和子答案

VCR 不调用额外裁判模型，对模型写出的固定句式作确定性核验：

- 正面声明“文档回答第 k 跳、答案是 A”：文档必须是第 k 跳标注支持文档，A 与该跳金标子答案的 F1 至少 0.5。
- 负面声明“文档不回答”：只有该文档不是任何一跳的支持文档时才判正确。它不是任意语义的否定判断器。
- 未知标题、错误跳号等无效声明判错；每条正确 +1，错误 −1，同轮求和后截到 [−1,1]，记作 c_t。没解析到声明时为 0，正负声明也可能抵消为 0。

```text
该轮 assistant token 优势 = A_GRPO + 0.5 × c_t
提示与工具 observation：仍不进入训练 loss
```

金标分解只用于训练监督和离线审计，不提供给评测时的 actor。固定正则、标题匹配和子答案 F1 不是通用自然语言推理验证，更不证明因果或医学蕴含。

这与 IGPO 的差别很具体：IGPO 问“读完后，金标答案似然涨了多少”；VCR 问“模型刚才对文档作用的明确声明，是否符合本题标注”。后者牺牲了表达的通用性，换来当前任务里更直接的检查对象。

### 8.3 离线相关通过，但历史执行顺序也如实保留

门控要求在同起点 GRPO 的训练轨迹上，平均声明奖励与终局的组内 Spearman≥0.30，仍写声明的轨迹比例≥80%。

| 门控统计 | 已完成 805 组时 | 完整 1,024 组复算 |
|---|---:|---:|
| 声明奖励与终局组内 Spearman | 0.414 | 0.438 |
| 仍写声明的轨迹比例 | 98.9% | 99.0% |
| 有错误声明的轨迹 EM | 29.3% | 29.5% |
| 声明全对的轨迹 EM | 84.0% | 84.2% |

两次都通过，但相关性本身不是加这个奖励一定有效的证明，仍需同起点训练对照。

历史上按明确的用户指示，VCR 在 GRPO-ERR 完成前使用已有 805 组门控启动；随后 IGPO-ERR 也并行运行，包括共卡阶段。不能把过程改写成“完整离线门控结束后所有训练严格串行”，也不能拿三组当时的每步耗时做公平速度比较。后续全量复算只说明门控结论一致，并不撤销早期部分数据决策这一事实。当前运行规则仍要求遵循仓库的资源准入和串行约束。

### 8.5 声明变化：开始会拒绝，但也会误拒

虚假正面声明数量约少 30%，负面声明从 14 条增加到 265 条，其中 174 条正确、91 条错误。模型不再一味说“这篇有用”，但也开始误拒部分支持材料。总声明数量和类型都变了，不能只挑 422→294 一个数字当作全面质量结论。

### 8.6 VCR v2：修正判分口径，但只停在离线门控

回看 VCR 的训练轨迹，判分规则本身有几处不合理：

- 否定声明只要指向任何一跳的支持文档就判错。dev2 上 VCR 被判错的 91 条否定声明里，37 条指向的是**其他跳**的支持文档：字面上没说错，但丢掉了下一跳线索。
- 子答案 F1 以 0.5 为界一刀切。GRPO-ERR 训练轨迹中有 132 条 F1 落在 [0.3, 0.5) 的正确文档声明被判为全错。
- 同一轮先求和再截断，一对一错会互相抵消；重复声明已确立的事实仍然加分；也不检查声明的文档是否真的读过。

v2 改为按"进展"给分：Φ_t 是到第 t 轮为止，各跳已确立的最高子答案 F1 的平均（只计已读、且指向该跳支持文档的正面声明），每轮奖励为 `ΔΦ_t + 0.1 × 正确否定数 − 0.5 × 错误声明数`。它借用势函数差分的形式，但只加在当前轮、另有惩罚项，因此**不具备**势函数塑形的策略不变性保证。

| 离线门控（GRPO-ERR 训练轨迹，1,024 组） | v1 | v2 |
|---|---:|---:|
| 轨迹信号与终局奖励的组内 Spearman | 0.438 | 0.488 |
| 含错误声明的轮次得到负奖励 | — | 98.7% |
| 确立新事实的轮次得到正奖励 | — | 98.8% |

三项门控都通过。但相关性提高的相当一部分来自最后一跳：最后一跳的子答案就是最终答案，与终局奖励部分同义；只看中间跳时，相关性只有 0.22，与 IGPO 信息增益的 0.17 同一量级。**v2 没有训练**，下一节的 9B 实验仍使用 v1 的判分规则。

### 8.7 扩展到 9B：加性 VCR 的问题，与保号的乘性形式

把基座换成 Qwen3.5-9B，其余全部不变：同一份 ERR SFT 数据（LoRA r=8、750 步、56 分钟），同一份 1,024 道 RL 题和题序，每题 4 条轨迹、2,048 次更新，同一评测协议。单卡 RTX 5090，显存上限 25 GiB，每组 RL 约 9–10 小时。

| test，512 题 | 未微调 9B | ERR SFT | GRPO | 加性 VCR | 乘性 VCR |
|---|---:|---:|---:|---:|---:|
| EM | 45.51% | 62.50% | 66.99% | 65.82% | **68.95%** |
| F1 | 55.30% | 70.62% | 75.00% | 73.88% | **77.33%** |
| 证据完整率 | 29.10% | 66.60% | 77.34% | 73.63% | **78.32%** |
| 提前停止率 ↓ | 38.67% | 26.17% | 17.58% | 13.67% | **12.70%** |
| dev2 EM | 50.00% | 66.80% | 70.90% | **72.07%** | 67.97% |

先看 SFT 和 GRPO：

- ERR SFT 相对未微调 9B，两个划分的 EM 都高约 17 pp。但未微调 9B 的格式合规只有约 81%，9B 也没有做相同静态材料的对照，所以这部分不能拆成"协议适配"和"答题能力"各占多少。
- GRPO 相对 ERR SFT：dev2 +4.10 pp [+0.98, +7.23]，test +4.49 pp [+1.17, +7.81]，两个划分的区间都不含零。

**加性 VCR 在 9B 上没有复现 2B 的结果。** EM 与 GRPO 持平（dev2 +1.17、test −1.17，都不显著），test 提前停止下降 3.91 pp [−7.23, −0.59]，但 test 证据完整率反而**下降** 3.71 pp [−7.03, −0.59]。

训练轨迹给出了一个可量化的解释：

| 训练组类型 | 2B GRPO | 9B GRPO | 9B 加性 VCR | 9B 乘性 VCR |
|---|---:|---:|---:|---:|
| 终局奖励有区分度 | 57.5% | 49.9% | 37.4% | 50.9% |
| 零方差：4 条全拿满分 | 28.1% | 37.5% | 44.6% | 38.1% |
| 零方差：4 条全 0 分 | 11.1% | 8.4% | 9.0% | 6.2% |
| 零方差：其他同分（含全 −2） | 3.2% | 4.2% | 9.0% | 4.9% |

零方差组的 GRPO 优势为 0，加性形式 `A + 0.5·c_t` 在这些组里只剩声明项。9B 加性 VCR 训练中有 62.6% 的组属于这种情况，其中约七成是 4 条都已答对的组。另外，`A + 0.5·c_t` 还可能把失败轨迹中某一轮的优势翻成正值。这能解释证据完整率为什么下降，但**没有做消融验证**。

乘性形式只改了这一行：

```text
加性：A_t = A_GRPO + 0.5 · c_t
乘性：A_t = A_GRPO · clip(exp(sign(A_GRPO) · c_t), 0.8, 1.2)
```

成功轨迹里声明正确的轮次最多 ×1.2、错误的 ×0.8；失败轨迹反过来，错误声明多罚、正确声明少罚。它有两个加性形式没有的性质：**不改变优势符号；组内零方差时不产生信号**。代价是在零方差组里也不再提供任何额外信号。

| 9B 同题差值，百分点 | dev2，95% 区间 | test，95% 区间 |
|---|---|---|
| 乘性 VCR − GRPO，EM | −2.93 [−6.25, +0.39] | +1.95 [−1.37, +5.47] |
| 乘性 VCR − GRPO，提前停止率 | −5.86 [−8.59, −3.12] | −4.88 [−7.81, −1.95] |
| 乘性 VCR − GRPO，证据完整率 | +0.39 [−2.34, +2.93] | +0.98 [−1.95, +3.71] |
| 乘性 VCR − 加性 VCR，证据完整率 | +0.98 [−1.95, +3.91] | +4.69 [+1.37, +8.01] |

乘性 VCR 的 test EM 68.95% 是 9B 上的最高值，**第一次超过同起点 GRPO**（+1.95 pp，净多答对 10 题）。这个进展要连同它的限定一起记录：

1. 配对区间含零；dev2 上方向相反，−2.93 pp 接近显著地变差；dev2 与 test 合并为 −0.49 pp [−2.83, +1.86]。
2. 乘性形式是在看过加性 VCR 的 test 结果之后设计的，没有做离线门控，也跳过了 4 步探针。test 因此参与了方法迭代。
3. 单训练种子。

两个划分一致、区间不含零的，仍然是行为变化：提前停止率下降，并且不再像加性形式那样损失证据完整率。代价同样保留：乘性 VCR 的 test 非法调用率从 GRPO 的 0.2% 升到 2.5%，阅读次数多约 15%。

最后，零方差组还剩多少可以挽回？4 条全拿满分的组占大多数，这些题模型已经会了，问题在于浪费采样，而不是缺少信用分配。真正"该学却学不到"的是 4 条全 0 的组，9B GRPO 中共 86 组。离线检查发现，其中只有 27 组的 4 条轨迹在 v2 进展 Φ 上有差异。也就是说，即使只在这些组里引入过程信号，最多也只能多救回约 2.6% 的组。这项检查来自研究档案中的训练轨迹，没有写入公开 JSON。

<a id="credit-gates"></a>

### 8.8 两次 token 级信用分配的离线门控：都没有通过

9B 的结果把问题推到一个具体的位置：组内零方差（9B GRPO 约 50%）与"同一个优势铺满整条轨迹"。两个方向各做了一次离线门控，阈值都在看结果前写入研究记录。

**门控一：按 token 熵加权优势。** 在 2B GRPO 末段 1/8 的 494 条训练轨迹上，用最终适配器重算每个助手 token 的熵，并按字符区间给 token 分类。

| 位置 | token 占比 | 平均熵 | 占总熵质量 |
|---|---:|---:|---:|
| 推理句措辞 | 17.7% | 0.318 | 50.1% |
| 检索词 | 4.5% | 0.834 | 33.4% |
| 选哪篇文档 | 2.4% | 0.109 | 2.3% |
| 停 / 继续 | 2.2% | 0.010 | 0.2% |
| 答案 | 1.2% | 0.020 | 0.2% |

决策类 token 在熵最高的 20% 中占 74.5%、在全部 token 中占 28.1%，富集 2.65 倍，**门控 1（≥1.5）通过**。但停/继续的熵中位数只有 0.0008，远低于全体的 80 分位数 0.0096，**门控 2 未通过**。提前停止的轨迹在这个位置的熵同样很低。结论：高熵确实标记"决策"，但标记的是措辞与检索词的自由度；此前诊断出的三个失败点——过早停止、选错文档、答错——模型都是高置信度的，按熵加权够不着它们。（声明的结论规则没有覆盖"只过门控 1"这一情形，这一缺口已如实记录。）

**门控二：在停止点强制分叉。** 既然策略几乎不会自己选择继续，那就从外部强制。取 2B GRPO 中四条轨迹全部得 0 的零方差组（114 个，其中 74 个有可续轨迹），复原作答前的环境状态，每条可续轨迹采 2 条强制继续分支和 2 条自由重采分支（对照：检验普通采样方差是否就够）。

| | 强制继续 | 自由重采 |
|---|---:|---:|
| 恢复信号的组 | 21.6%（16/74） | 2.7%（2/74） |
| 非零分支的平均奖励 | 0.664 | 0.476 |
| 全部分支的平均奖励 | −0.119 | −0.010 |
| 非法调用率 | 9.4% | 0.7% |

强制分叉显著优于普通采样（+18.9 pp），一旦继续成功收益也大（43 个非零分支中 38 个是答案与证据同时改善）。但恢复率 21.6% 低于事先声明的 30%，**门控未通过**；恢复的 16 个组只占全部训练组的 1.56%，而分支整体平均奖励为负，其中的 −2 来自被强制执行的动作而非策略自身选择，并入训练会教模型回避被强制的动作。按规则放弃，且不做探索性覆盖运行。

两次门控合起来指向同一件事：全 0 零方差组里，456 条轨迹有 446 条是**答案错**、只有 10 条是证据缺失，249 条已经用尽检索预算。零方差不是信用分配没做好，主要是题目要么已经会了（全对组占多数），要么卡在答题环节。这与单侧 CSC 的教训一致，也是 8.7 节之后仍然没有解决的部分。

### 8.9 答题环节诊断：约一半的"证据齐全却答错"是答案形式

8.8 节两次门控都指回同一处：证据齐全之后的答题。把已记录预测里"引用了全部支持文档但 EM = 0"的题按答案分类（`python -m evisearch.evaluation.answer_errors`）：

| test，证据齐全却答错的构成 | 2B GRPO | 2B VCR | 9B GRPO | 9B 乘性 VCR |
|---|---:|---:|---:|---:|
| 这类题占全部 512 题 | 16.8% | 19.3% | 16.4% | 16.0% |
| 近似（形式问题） | 47% | 39% | 44% | 46% |
| 支持文档内取错片段 | 37% | 42% | 38% | 39% |
| 桥接实体（答成中间跳） | 10% | 10% | 13% | 9% |
| 干扰文档 / 不在语料 | 5% | 8% | 5% | 4% |

三类错误的实例很能说明区别。**形式**：`"Alfred Gough and Miles Millar"` 对金标 `["Alfred Gough", "Miles Millar"]`——两位创作者都答对了，金标把他们拆成两个别名；`"207.77 million"` 对 `"207.77 million people"`。**取错片段**：问"何时被弹劾"，答 `"1788 and 1795"`（审判年份），金标 `1786`。**桥接实体**：问"Mistress 的制片人在《教父》里演谁"，答第一跳的 `"Robert De Niro"` 而不是 `"Vito Corleone"`——这正是多跳问答的典型失败。

放到全部题上看，以"金标与预测互为子串"为宽松判据，**每个分支的 EM 都被低估 9–12 个百分点**，而且幅度相当一致（2B GRPO 11.7、2B VCR 10.4、9B GRPO 10.7、9B 乘性 VCR 11.3，均为 test）。其中"多说了一个词"与"少说了一个词"各约一半；后者可能过度宽容（答 `"Nissan"` 而金标是 `"Nissan Altima"` 也会算对），所以 9–12 pp 是**上界**，保守下界约 4–7 pp。

重要的是**结论不随判据改变**：9B 乘性 VCR 对 GRPO 在 test 上由 +1.95 变成 +2.54、区间仍含零；2B VCR 对 GRPO 由 +0.59 变成 −0.78、两者都含零，反而更支持"VCR 没有建立 EM 优势"；VCR 对 IGPO 的 test 优势由 +4.30 变成 +4.88，依然成立。所以这不是一个会改写排名的发现，而是一个关于"剩下的差距是什么"的发现。

根因不在示范数据：冻结 SFT 的 1,320 条通用 Agent 示范，最终答案与金标 **100% 完全一致**，形式漂移只发生在未见题上。更合理的解释是奖励与评测口径不一致——终局奖励按答案 token 集合 F1 计分，`"207.77 million"` 能拿 0.857，RL 几乎没有动力删掉多余的词，而评测用 EM 判它零分。这一点项目早先就设计过修正（把 RL 的答案项对齐 EM），其离线门控以 0.0015 之差未通过，当时只衡量了机制而没有衡量问题的规模；现在规模清楚了，但门控阈值不在事后修改。

### 9.3 还没有被回答的问题

当前缺少的是几组明确证据，而不是另一个算法名字：

- **稳定性：** 当前 GRPO/IGPO/VCR 主对照只有一个训练种子；旧 GRPO 的三种子范围不能替代新起点的重复实验。
- **新的泛化检验：** test 与训练隔离，但在长期研究中被反复查看；dev2 也用于筛选。需要新冻结、在设计确定后才评测的数据，不能继续称旧集为盲测。
- **SFT 与 RL 的净贡献：** ERR SFT 缺完整 test 独立评测；ERR 同时继承干扰增强并增加监督文本和 token，尚不能把全部变化只归因于某一句推理模板。
- **相同证据上的答题能力：** 各策略完整证据子集不同。需要固定相同题目、相同材料的对照，区分新纳入题更难与模型利用证据能力改变。8.9 节已把这部分拆开：证据齐全仍答错的题中约 45% 是答案形式、约 38% 是在正确文档里取错片段、约 10% 是答成中间跳，后两类才是待解决的推理问题。
- **声明核验的外推：** 当前依赖 MuSiQue 分解、固定句式和答案匹配，尚未证明可迁移到任意表达、开放语料或医学语义判断。
- **零方差组与 token 级信用：** 两项离线门控都已完成，结论都是否定的（见 8.8 节）。熵加权：高熵 token 确实集中在决策类（富集 2.65 倍），但几乎全是推理句措辞和检索词；停/继续、答案、选文档合计只占 2.7% 的熵质量，模型在这三处近乎确定，错误是高置信度错误。强制分叉：能让 21.6% 的全 0 组恢复信号（自由重采仅 2.7%），但低于事先声明的 30%，且分支平均奖励为负。仍然开放的是**答题环节**——证据齐全时如何稳定答对，两次诊断都指回这里，8.9 节进一步把它拆成了形式、取错片段与中间跳三部分。
- **成本与收益：** 部分历史训练并行且共享 GPU；完整方法成本应包含数据、教师、离线门控、失败重跑与评测。现有分段审计不应拼成一个未经核实的全项目账单。
