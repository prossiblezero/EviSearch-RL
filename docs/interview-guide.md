## 1. 项目讲述

### 90 秒版

> 这个项目做的是多跳问答的 Search Agent。单轮 RAG 一次检索拿不全桥接证据，答案也没法核验，所以我让一个 2B 小模型自己多轮搜索、阅读、保存证据，最后只能引用自己存下的原文作答。
>
> 我搭了一个本地检索环境，有搜索、阅读、保存证据、作答四个动作和工具预算。用 DeepSeek 在真实环境里合成了 1,800 条轨迹做 SFT，再用 GRPO 做在线强化学习，奖励是答案 F1 乘以证据 F1，违规一律记 −2。
>
> 训练下来发现，GRPO、DAPO、GSPO、IGPO 这些算法都卡在同一个水平。排查后定位到原因在数据：教师合成示范时能看到答案，所以示范里从来没有“判断这篇文档有没有用”，学生学成了“读到就存”。我做了两件事：一是在示范里加入逐跳的相关性推理；二是提出可验证声明奖励 VCR，把模型自己写的“这篇文档回答了第几跳”拿去和标注核对，作为每一轮的过程奖励。
>
> 结果上，同一起点下 VCR 把提前停止率从 28% 降到 17%，test EM 是 56.8%，比 IGPO 的信息增益奖励高 4.3 个点。换到 9B 后，我发现约六成训练组终局零方差，加性过程奖励在这些组里喧宾夺主，于是改成保号、有界的乘性形式：test EM 69.0%，第一次超过同起点 GRPO 的 67.0%，提前停止率在两个评测集上都显著下降。

### 3 分钟版（在 90 秒版基础上，每段多说一句）

1. **背景（20 秒）**：多跳问题例如“WNSP 电台所在州的州长任期多长”，要先查出电台在 Alabama，再查 Alabama 州长任期。单轮检索常常只拿到一跳。目标是答对，并且答案能追溯到原文。
2. **环境（30 秒）**：MuSiQue 数据，每题一组固定候选文档，里面混着干扰段落，本地 BM25 排序。动作是 search、read、add_evidence 和最终 JSON 答案；预算每题 3 次搜索、8 次阅读、8 次保存。search 只发现候选，read 打开原文，add_evidence 保存已读片段，最终引用必须指向已保存的证据（代码：[environment.py](../evisearch/environment.py)）。
3. **数据（30 秒）**：教师在真实工具环境里跑出候选轨迹，按格式、引用、证据完整度过滤，再在环境里确定性回放一遍，保证工具返回与记录完全一致，最后留下 1,800 条。混入通用、代码、安全数据防遗忘，共 6,000 条。RL 用另外 1,024 道题，dev、test 各 512 道，划分先冻结（代码：[data/](../evisearch/data/)）。
4. **训练与奖励（50 秒）**：Qwen3.5-2B 先做 LoRA SFT，只对 assistant token 算损失。然后 GRPO：每题采 4 条完整轨迹，组内标准化得到优势。终局奖励是答案 F1 × 证据 F1，乘法让“答对但没证据”拿不到分；格式错、非法或重复引用、非法调用、截断统一 −2（代码：[training/trainer.py](../evisearch/training/trainer.py)）。
5. **发现与改进（40 秒）**：多种 RL 都停在同一水平。分析发现模型读到无关文档后 95% 以上直接存下，RL 也改不掉；原因是示范由能看到答案的教师生成，没有任何相关性判断。于是在示范的每次阅读后加一句“这篇文档回答了第几跳、得到什么实体”，再用 VCR 逐轮核验这些声明给奖励（代码：[data/rationale.py](../evisearch/data/rationale.py)、[training/claims.py](../evisearch/training/claims.py)、[training/vcr.py](../evisearch/training/vcr.py)）。
6. **结果（20 秒）**：同起点三组对比，VCR 提前停止率最低（17% 对 GRPO 28%），证据完整率最高，test EM 56.8%；比 IGPO 高 4.3 个点。和普通 GRPO 的 EM 差距不显著，VCR 的明确收益在行为上。

## 3. 指标定义

仓库里的正式定义见 [results/README.md](../results/README.md) 的“协议与指标”。声明准确率在仓库中没有单独定义，下面是统计口径。

| 指标 | 定义 | 一句话 |
|---|---|---|
| **EM** | 答案规范化（小写、去标点、去 a/an/the）后与标准答案或任一别名完全相同记 1，否则 0 | 主指标，严格 |
| **F1** | 预测与标准答案按词计算重合的准确率与召回率，取调和平均，多别名取最高。报告用词频口径，训练奖励用 token-set 口径，两者不混用 | “接近正确”也给分 |
| **证据 F1** | 引用的文档集合与标注支持文档集合的 F1 | 引用准不准、全不全 |
| **证据完整率** | 引用覆盖了全部标注支持文档的题目占比 | 检索做全了没有 |
| **提前停止率** | 最终格式有效、证据不全、且 search 调用少于 3 次的题目占比 | 还能搜却不搜 |
| **声明准确率** | 模型写出的相关性声明中，按 [claims.py](../evisearch/training/claims.py) 规则核验为正确的比例（dev2 审计） | 判断得对不对 |

声明核验规则（[第 5 课](learning/05-vcr.md)有可运行例子）：
- “X answers step k: A” 正确，当且仅当标题属于题目语料、跳号有效、X 是第 k 跳的标注支持文档，且 A 与子答案的词频 F1 ≥ 0.5。
- “Y does not answer step k” 正确，当且仅当 Y 不是**任何一跳**的支持文档。
- 不存在的标题、越界跳号都算错。

## 4. 核心概念

**GRPO**：同一问题采样一组回答（这里 4 条），组内奖励减均值、除以标准差得到优势，不需要价值网络；再用 PPO 式截断比率更新，加 KL 约束。缺点是一组奖励完全相同时优势全为 0，这组学不到东西（[第 4 课](learning/04-grpo.md)）。

**DAPO**：GRPO 的四处改动：非对称截断（clip-higher）、动态采样（丢掉奖励全相同的组、重新采样）、token 级损失平均、超长惩罚。本项目实测它把有效更新提高 76%，但多花 2.3 倍生成 token，EM 基本不变。

**GSPO**：重要性比率与截断从逐 token 改为整条序列级，训练更稳定，常用于 MoE 模型。

**IGPO**：每一轮计算“模型生成标准答案的对数概率”比上一轮提高了多少，作为这一轮的过程奖励（实现：[training/advantages.py](../evisearch/training/advantages.py) 的 `turn_advantages`）。本项目里它与最终答对的相关性只有 ρ=0.17。

**VCR（本项目提出）**：模型每轮写出可检查的声明，训练时与标注核对，正确 +1、错误 −1，每轮求和后截到 [−1, 1]，再以 `A_token = A_GRPO + 0.5 × c_t` 写入该轮所有 assistant token，工具观察的优势为 0。与 IGPO 的区别：IGPO 奖励“答案似然有没有升高”，是代理信号；VCR 奖励“这一步说的事实对不对”，可以直接核验。它不需要额外的奖励模型或大模型裁判。

**在线蒸馏（OPD）**：学生自己采样，教师给学生生成的每个 token 打分，奖励为教师对数概率减学生对数概率（负的逐 token 反向 KL），信号稠密。本项目用 SFT 后的 Qwen3.5-9B 当教师，与 2B 学生共用分词器。

**LoRA**：冻结原模型，只训练低秩增量矩阵，这里 r=8、alpha=16（[configs/lora.json](../configs/lora.json)）。

**损失掩码**：工具返回的内容不是模型生成的，这部分 token 的损失必须为 0，否则模型会去学习预测检索结果（[第 3 课](learning/03-data-and-sft.md)）。

**KL 参考模型**：RL 时冻结一份 SFT 权重做参考，KL 系数 β=0.02。三组 RL 共用同一个冻结参考。

## 5. 高频问答

### 数据与环境

**Q：为什么用 MuSiQue？**
A：专门构造的多跳题，每题自带子问题分解和每跳的支持段落标注，所以既能算证据 F1，也能核验 VCR 的声明；它还刻意去掉了单跳就能答的捷径。

**Q：为什么用本地 BM25，不用稠密检索或网络搜索？**
A：可复现、成本低，并且让瓶颈落在 Agent 的决策上，而不是检索器质量上。我测过上限：每一跳都用标准子问题去查，85% 的题能把支持文档都搜进前 5，BM25 不是主要瓶颈。

**Q：1,800 条示范怎么保证质量？**
A：三层过滤：格式与引用合法；证据完整、答案正确；在环境里确定性回放每个工具调用，返回内容必须与记录完全一致，防止教师编造工具结果。

**Q：为什么混入通用、代码、安全数据？**
A：防止灾难性遗忘。对话条数和监督 token 数分开统计，Agent 数据约占监督 token 的 43%。

**Q：相关性推理怎么生成的？**
A：用 MuSiQue 的子问题分解做模板（[data/rationale.py](../evisearch/data/rationale.py)）。读到第 k 跳的支持文档时写“回答了第 k 跳，得到某实体”，读到无关文档时写“没有回答第 k 跳，换一篇”。只陈述示范上下文里已经读到的内容，所以不会泄露答案。

**Q：有没有数据泄漏？**
A：SFT、RL、dev、test 按问题 id、规范化问题文本和子问题 id 三重去重，划分在实验前冻结。

### 奖励与 reward hacking

**Q：为什么是答案 F1 × 证据 F1，而不是相加？**
A：相加的话，只答不引或只引不答都能拿一半分；乘法要求两者都对，引用必须真的支持答案。

**Q：为什么罚 −2？**
A：正常奖励在 [0, 1]，−2 保证违规轨迹在组内一定排最后、拿负优势，不会因为“答对但伪造引用”被奖励。

**Q：防了哪些 reward hacking？**
A：
1. 环境层面：必须先搜到才能读、先读到才能存，引用必须来自已保存证据。
2. 证据保存幂等，工具调用本身不给奖励，刷调用次数没用；工具预算有硬上限。
3. 审计发现的漏洞：IGPO 会让失败调用的轮次拿到正优势；别名表有 “a”“Year” 这类退化别名，输出 “the” 就可能被判对。

**Q：VCR 会不会被 hack？比如少写声明，或者只写好写的声明？**
A：这是真实风险。现有防护：不写声明的轮次奖励为 0；每轮截断在 [−1, 1]，刷大量声明没用；λ=0.5，终局奖励仍占主导。实测 RL 后 99% 的轨迹仍在写声明，准确率 63% → 69%，声明没有消失。但 VCR 也有误拒：它开始写更多“这篇不相关”，其中也有判断错的。更彻底的做法是要求每次阅读后必须写声明，或按声明数归一化。

**Q：训练时用了标注，算不算作弊？**
A：标注只在训练时用于算奖励和离线审计，评测时模型提示里没有任何标注，和用标准答案算 EM 奖励是同一类做法。代价是依赖数据集有子问题分解标注。

### 训练

**Q：GRPO 的关键超参？**
A：每组 4 条、1,024 组、每组两次更新，共 2,048 步；学习率 1e-5；β=0.02；截断 ε=0.2；采样温度 1.0、top_p 0.95；单轮最多 512 新 token，轨迹预算 6,144 token。单张 RTX 5090 一组 RL 约 4–6 小时，SFT 约 35 分钟（[configs/rl-reference.json](../configs/rl-reference.json)）。

**Q：为什么每组只采 4 条？**
A：显存和时间限制。我也做过模拟：固定总轨迹预算时，组越大，“组内有对错差异”的组数反而越少（[演化故事 4.5 节](evolution.md)）。

**Q：在线蒸馏为什么没效果？**
A：9B 教师总分更高，但只做过 SFT，搜索比 RL 后的学生更少（平均 5.7 次工具调用对 6.8 次）。蒸馏把学生往教师的行为上拉，把 RL 学到的“多搜一点”蒸馏回去，提前停止率反而上升。教训：教师必须在被蒸馏的那个行为维度上比学生强。

**Q：DAPO 为什么没效果？**
A：它解决“奖励全相同的组没有梯度”，有效更新多了 76%，EM 却几乎不变，说明瓶颈不在梯度数量，而在策略本身的行为模式。

### 发现与诊断

**Q：怎么发现瓶颈在数据而不在算法？**
A：三步（[演化故事第 4、7 章](evolution.md)）：
1. 多种 RL 结果都一样，DAPO 把有效更新提高 76% 也没用，排除“信号太少”。
2. pass@16：RL 前后都是 78%，RL 只提高了 pass@1，说明 RL 在放大已有行为。
3. 行为统计：读到无关文档后 95% 以上直接存下，SFT 与各种 RL 之后都是这样；回头查示范，教师生成时看得到参考答案，97.5% 的示范恰好只读支持文档，从没出现“读错了换一篇”。

**Q：为什么 RL 改不掉？**
A：混杂效应。策略只在迷路时才会多读，所以在它自己的轨迹里，“多读”总是和“失败”一起出现，outcome 奖励就把“多读”当成失败的原因来惩罚。我做过干预实验：强制每次多读一篇，EM 下降 10.7 个点，说明问题不在读得少，而在判断不出哪篇有用。

**Q：为什么 IGPO 的过程奖励没用？**
A：IG 信号和“读对文档”相关（读支持文档 IG +0.46，读干扰文档 −0.40），但和“最终答对”的相关性只有 0.17。它衡量的是“教师强制下标准答案是否更可能”，而不是“策略能否据此答对”。VCR 声明奖励和结果的组内相关性是 0.44。

### 实验与结果

**Q：56.8% 显著吗？几个种子？**
A：单种子。和同起点普通 GRPO（56.25%）相比，test EM 差 +0.59 个点，区间 [−2.93, +4.30]，不显著；dev 上 VCR 还低 1.37 个点。VCR 明确的收益在行为上：提前停止率在 test 和 dev 上分别降了 10.9 和 6.8 个点，两个划分区间都不含 0。另外 GRPO 我跑过三个种子，test EM 在 52.3%–53.9% 之间波动，所以 1 个点以内的差异要看作噪声。

**Q：那 EM 为什么没继续涨？**
A：VCR 让检索更完整（证据完整率 64% → 67%），但证据齐全题上的答对率从 73.9% 降到 71.2%，抵消了收益；不过纳入的题可能更难，不能全归因于推理退化。如何把多拿到的证据用对，是还没解决的部分。

**Q：Base 只有 6.3% 是不是因为不会用工具？**
A：对。Base 在 Agent 模式下格式合规率只有 12%；给相同的静态检索材料时，Base 13.7%、SFT 19.0%。所以 SFT 的大幅提升里很大一部分是协议和工具控制，不全是推理能力。

**Q：做了哪些消融？**
A：同一个相关性推理 SFT 起点上，GRPO、IGPO、VCR 三组只改优势计算；原教师 SFT 起点上做了 GRPO / DAPO / GSPO / IGPO / 在线蒸馏 / 反事实停止信用，并扫描了学习率、KL 系数、LoRA 秩；另有 5 个方法在离线验证阶段被排除（[演化故事 9.2 节](evolution.md)）。

### 扩展到 9B

**Q：为什么从加性 VCR 改成乘性？**
A：9B 上加性 VCR 没有复现 2B 的结果，test 证据完整率还掉了 3.7 个点。查训练轨迹发现，9B 加性 VCR 有 62.6% 的组 4 条轨迹终局得分完全相同，这些组的 GRPO 优势是 0，`A + 0.5·c` 里只剩声明项，等于大半训练在学"把声明写对"，而不是"把题答对"。加性形式还会把失败轨迹里写对声明的那一轮翻成正优势。乘性形式 `A × clip(exp(sign(A)·c), 0.8, 1.2)` 不改变符号、A=0 时为 0，只在终局信号上做 ±20% 的微调。

**Q：乘性 VCR 在 9B 上超过 GRPO 了，显著吗？**
A：不显著。test 68.95% 对 66.99%，+1.95 个点，区间 [−1.37, +5.47]；dev 上反而低 2.93 个点；两个集合并接近 0。而且这个形式是看过加性版 test 结果才设计的，test 已经参与了迭代。所以我把它记为"首次超过 GRPO 的进展"，但能确定的是行为：提前停止率在 dev 和 test 上分别降 5.9 和 4.9 个点，区间都不含 0；相对加性版，test 证据完整率高 4.7 个点（显著）。

**Q：乘性形式在零方差组里也没信号，零方差问题怎么解决？**
A：先看零方差组是什么。9B GRPO 里约 50% 的组零方差，其中 37.5% 是 4 条全对，这些题已经会了，问题是浪费采样，应该靠采样策略解决，而不是优势公式。真正学不到的是 4 条全 0 的 8.4%，共 86 组；离线看，只有 27 组的 4 条轨迹在逐跳进展上有差异，也就是说过程奖励最多再救回约 2.6% 的组。另外要注意：任何"把终局优势按 token 重新分配"的方法，比如按熵加权，形式都是 A × w_t，A=0 时一样为 0，也解决不了零方差。

**Q：那 token 级信用分配有没有用？**
A：有可能，但作用对象是有区分度的那一半组。训练时平均 token 熵只有约 0.1 nats，大部分 token 是 JSON、工具标签、照抄的 id；真正的决策点在结构上是已知的：停还是继续、读哪篇、检索词、答案、声明。高熵 token 那篇论文在 8B 上只是与全量梯度持平、32B 才明显提升，所以在 2B / 9B 上我会先离线检查高熵 token 是否落在这些决策点上，再决定是按熵加权还是按结构加权。

**Q：数据集的题目和答案长什么样？训练数据呢？**
A：见[数据集说明与样例](dataset-examples.md)。一句话：MuSiQue 2–3 跳问题，每题约 20 篇候选段落，2–3 篇支持、其余是同主题干扰；答案是短实体或数字，约三分之一带别名；SFT 6,000 条对话，其中 1,800 条是教师在真实环境里生成并回放校验的 Agent 轨迹；RL 1,024 道独立题目，只给问题，奖励由环境按金标答案和支持段落计算。

**Q：离线验证是什么？**
A：花几个小时训练之前，先在已有轨迹上算出新方法的信号，检查它是否奖励了想鼓励的行为，阈值事先写好、不事后修改。例如 VCR 的门槛是“声明奖励与结果的组内相关性 ≥ 0.30”，实测 0.44。

## 6. 结论边界

1. **EM 与行为分开看**：同起点下，VCR 与普通 GRPO 的 EM 差在两个划分上都不显著（test +0.59，dev −1.37）；提前停止率在两个划分上都显著下降（test −10.9、dev −6.8，区间不含 0）。
2. **VCR 对 IGPO 的 EM 优势在 test 上成立**（+4.30，区间 [0.20, 8.40]），dev 上两者接近。
3. **行为指标各有侧重**：VCR 的提前停止率、证据完整率、声明准确率最好；读到干扰后的补救率 IGPO 更高（19.5% 对 13.9%）；F1 普通 GRPO 更高。
4. **阶段数字不是单因素贡献**：6.3% → 43.8% → 53.9% 来自原教师 SFT 起点；相关性推理 SFT 起点没有单独的 test 评测，其 dev EM 为 58.0%（原教师 SFT 54.5%）。
5. **相关性推理由模板生成**，依据数据集的子问题分解。
6. **医学轨迹**：1,800 条中 480 条为 MedHop，其证据为实体共现代理，不代表经过验证的医学蕴含。
7. **单训练种子**；GRPO 三种子 test EM 在 52.3%–53.9%。test 在研究过程中被多次查看，方法选择以 dev 为准。
8. **硬件**：单张 RTX 5090（32 GB），共享机器。
9. **9B 乘性 VCR**：test EM 超过 GRPO 但区间含 0、dev 方向相反，且设计时已看过加性版 test 结果、没有离线验证；9B 的未微调基线没有静态材料对照，SFT 的 +17 个点不能拆成格式与答题各占多少。
