# 从“把答案搜出来”到“核对模型的证据判断”

这个项目最初想回答一个朴素的问题：小模型经过 SFT 和在线强化学习，能不能更可靠地检索资料、给出有来源的答案？后来真正推动设计变化的，并不是不断换一个新算法，而是逐渐发现：格式正确、搜到文档、保存证据、理解证据、最后答对，是几件不同的事。

本文将早期到当前的研究合并为一条故事。它保留失败、门控未通过和改变方向的原因，但不要求读者学习历史代码。现在怎样运行、每个模块怎样工作，分别见[复现说明](reproduction.md)与[六课教程](learning/README.md)。

## 起点：先证明模型真的在用工具

最早的环境把检索与短片段阅读合在一个搜索工具里，最终答案附带文档引用。实验同时关注通用多跳问题和 MedHop 医学文献中的实体连接。这个阶段首先解决的是最基本的闭环：模型生成调用，工具真实执行，观察回到上下文，奖励可以核对。

很快就遇到一个解释问题：SFT 之后任务分数上涨，是模型更会找证据、更会推理，还是终于愿意按 JSON 协议回答？早期未适配模型在 Agent 模式下的格式失败很多，单看答案 EM 很容易把格式改善说成知识能力提升。

因此后来始终保留未经微调的 Base，并在相同 Agent 模式和相同静态材料模式下分别比较。相同静态材料把检索策略固定住，帮助区分协议、工具控制和答题变化。当前环境中，Base→原教师 SFT 的 Agent EM 为 6.25%→43.75%，而完全相同静态材料下为 13.67%→18.95%；两组数字描述的不是同一个能力变化。

医学扩展也暴露了任务定义的限制：药物与蛋白质在摘要中的共现路径，并不等于医学蕴含或因果关系；有些候选材料本身无法构造代理路径。这个问题不能用更多训练掩盖。当前主问题收敛到 MuSiQue 多跳证据检索，医学内容保留为有限的辅助诊断，始终标明代理含义。

**留下来的设计：** 真实工具执行、Base 对照、相同检索模式比较，以及对任务指标能力边界的明确说明。

## 第一处转折：证据奖励加入了公式，却未必加入了学习信号

直觉上，正确答案之外再奖励引用质量，模型就应该学会更好的引用。但 GRPO 用的是组内相对优势。若四条轨迹只有一条答对，或者答对轨迹的引用质量全一样，额外的证据系数可能不能提供新的组内区分。

早期实验因此不再只记录 reward 均值，而是检查多少组具有奖励差异、多少组证据项真正改变了优势。零方差组没有任务相对信号；它们可能还有 KL 引起的参数变化，但不能据此说任务策略学到了新东西。

接下来扩大数据和训练预算，对比 GRPO、DAPO、GSPO，以及利用答案似然变化的 IGPO。这个阶段的价值，是把采样预算、更新预算、额外采样、实际梯度和任务效果分开记录。方法名字更多了，证据标准却必须相同。

**留下来的设计：** 同一个 SFT 起点与冻结 reference；相同题序和预算；不删除零方差组、非法调用与失败样本；训练执行证据与任务收益分开报告。

## 第二处转折：搜索结果里出现过，不代表模型真的读过

搜索直接返回短片段的环境，让“找到”“读到”“选为证据”混在一起。模型可以引用一个检索结果 ID，却没有明确执行过阅读和保存。仅靠答案和引用表，难以定位检索链究竟在哪一步断了。

于是环境拆成 search、read、add_evidence：先发现候选，再打开原文，再保存可引用片段。最终答案只能引用已保存证据。工具 observation 记录剩余预算，原文片段保留字符偏移，重复保存幂等。

教师采集的第一次小规模试跑也没有一帆风顺。历史记录中，64 题试生成只得到 22 条合格通用示范，医学部分没有合格示范。逐条回放发现问题包括种子对当前校验器不可行、桥接实体检索不合适、分页遗漏、漏存中间文档和预算耗尽后仍继续调用。不能仅凭“强教师也失败”就归因于教师医学知识不足。

解决顺序因此是先检查任务与校验器是否一致，再处理工具描述、完整摘要阅读、短句柄和预算可见性，最后重新采集。教师示范必须真实执行、确定性回放，并保证 observation 不进入训练 loss。

生产数据随后形成 1,800 条 Agent 示范，与其他类别混合为 6,000 条 SFT 数据。这里有一个后来很重要的条件：生产示范采用答案与证据条件化的教师构造，最终 actor 提示再去掉这些特权标签。它提高了示范质量，却也让示范过于顺利。

**留下来的设计：** 工具职责分离、证据来源状态、可执行回放、assistant-only loss；同时承认教师示范构造中的特权信息和分布偏差。

## 为什么没有一直沿着“更复杂的过程奖励”走下去

多工具环境里的 GRPO 确实改善了检索表现，但“拿齐证据”和“利用证据答对”开始分离。历史 pass@k 诊断中，一些模型反复答错的问题已经拿齐过证据，仍会答成中间实体或没有走完多跳链。

IGPO 的离线诊断给出了一个细微但重要的结果：读取支持文档通常增加金标答案似然，读取干扰文档通常降低它，所以信号并非完全失效；但累计信号与终局回报关联较弱，部分失败动作在归一化和回传后仍可能拿到正优势。它测量“金标答案在这个前缀下更可能”，不保证“当前策略据此能够答对”。

不能从这里推出 IGPO 在所有任务上都无效。本项目真正得到的判断，是当前失败模式和这个代理信号没有充分对齐，继续修饰它未必触及主要瓶颈。

随后还尝试过将完美轨迹再监督、调整 KL、学习率与 LoRA 秩。少量表面改善没有在额外种子上形成稳定收益。原 GRPO 的 test EM 在三个种子中为 53.91%、52.34%、52.34%，提醒我们不要把单次约一个百分点的波动写成方法突破。

**留下来的设计：** 不用算法数量作为项目价值；先诊断失败阶段，关注信号是否对应真实行为，并保留种子不确定性。

## 几条看起来合理、但没有成为主线的路

为了不把每个想法都变成一次昂贵训练，后续方法先声明离线门控，再判断是否值得推进。门控也不是可以事后随意改写的成功条件。

| 尝试 | 为什么值得试 | 实际阻碍与取舍 |
|---|---|---|
| 证据状态优势 ESA | 在“检索结束、开始答题”处重采样，拆开两段信用 | 许多错误在同一状态下稳定重现，重采样没有产生足够新信号；门控未通过，未进入训练 |
| 特权提示自蒸馏 PE-OPD | 给同一模型额外推理链提示，期望形成更强教师 | 离线教师未表现出预期优势；未进入训练 |
| 反事实停止信用 CSC | 比较停下与继续搜索的回报，纠正过早停止 | 收益幅度门控未通过，保留失败结论后做了探索性训练；没有建立优于原 GRPO 的结果 |
| 大模型在线蒸馏 OPD | 用更大教师给学生采样 token 提供稠密反馈 | 教师评分能力与自主工具策略能力并不等价；教师门控部分未通过，探索性运行也没有确认收益 |
| 决策点蒸馏 DPD | 只教“继续还是停止”，减少无关 token 信号 | 教师没有额外优于 RL 学生的停止策略，门控未通过，未训练 |
| 干扰阅读示范 RAD | 教模型读错以后继续寻找证据 | 有小幅补救变化，但主要门控未通过，未继续对应 RL |
| 失败状态重启 FSR | 直接从读到干扰文档的状态采样补救 | 四次采样中能出现补救成功的组仅约 15%，未达门控，未训练 |

这些状态不能统称为“离线筛掉全部无效方案”。其中有未训练的方法，也有门控未过后明确声明的探索性训练；还有只完成数据/SFT 探索的路线。它们的负结果是研究的一部分。

共同教训逐渐清晰：更强的教师不一定更擅长当前工具协议；多采样不一定能创造策略分布中很少出现的正确行为；显式奖励“继续”也不一定改善继续之后的文档选择。

## 真正有用的线索：模型为什么把干扰文档当证据

逐条重放后发现，“读到干扰文档就保存”可能只是表面症状。缺失的支持证据大多发生在阅读之前：有的已出现在搜索结果里却没被打开，有的因为查询不对从未出现。单纯在示范里插入一篇干扰文档，没有解释它为什么不相关。

原来的 assistant 消息常常只有连续工具调用。对于一个 2B 模型，中间的相关性判断和桥接实体提取都要隐式完成。于是新的 SFT 数据在阅读后加入一句具体判断：这篇文档回答哪一跳、答案是什么；不相关时明确说明继续寻找。

这个改动在 dev2 上把 SFT EM 从 54.49% 提到 58.01%，但补救率只有约 5%，仍低于预先声明的 10% 门控。历史记录没有把它改成“全门控通过”，而是声明为探索性运行，继续训练普通 GRPO。

更关键的是，错误终于变得可见：模型会把不相关的文档明确写成“answers step k”。判断被写出来，就能检查；此前只能从最终答案猜测模型哪里想错，现在可以直接核对中间声明。

**留下来的设计：** 让中间判断可观察；数据增强与奖励设计围绕同一个可检查行为，而不是仅增加轨迹长度。

## 当前方案：用可验证声明反馈中间判断

VCR 验证固定句式声明的文档、跳号与子答案。每轮正确声明 +1、错误 −1，求和截到 [−1,1]，再以 λ=0.5 加到该轮的 GRPO 优势上。没有调用额外裁判模型，工具 observation 仍不参与 loss。

离线门控在同起点 GRPO 的训练轨迹上检查声明信号与终局回报的关系，以及策略是否仍然写声明。历史上先用训练进行中的 805 组进行门控，随后全量 1,024 组复算，结论一致。这个过程不应改写成“所有实验都在完整对照结束后才启动”。

最终比较保持同一个相关性推理 SFT 起点，分别训练普通 GRPO、IGPO 和 VCR。当前 test EM 为 56.25%、52.54%、56.84%。相对普通 GRPO，VCR 的 +0.59pp 配对区间包含零，F1 还下降了；因此答案准确率的改善没有被确立。

更明确的变化是 test 提前停止率从 28.12% 降至 17.19%，证据完整率从 64.26% 到 67.19%。dev2 上声明准确率从 63.2% 到 69.4%，干扰阅读后补救率从 2.3% 到 13.9%。这些行为变化与方法意图相符，但并未全部转化为更好的最终答案。

这里仍然有解释边界：VCR 依赖特权训练标注和固定句式；有些统计只来自 dev2；IGPO 在某个补救指标上更高；当前三组只有单训练种子，历史上还按明确指示并行运行，耗时不构成公平比较。

**当前保留的主线：** 同一环境、同一相关性推理 SFT 起点、三个对照奖励、统一评测。复杂的未选路线不再成为理解代码的前置依赖。

## 为什么整理成今天的仓库

研究阶段按版本累积代码很方便：每次尝试独立保存，旧结果容易回看。但一旦 `v5` 继承 `v4`、`v3` 和 `v2`，版本号就不再说明职责。新读者想理解一套系统，却必须猜哪些是仍在使用的组件，哪些只是一次实验的残留。

因此，公开仓库按环境、数据、训练、评测组织代码，把仍在使用的逻辑抽出，移除历史训练入口和旧报告。历史没有被包装成不存在：完整研究档案留在本地，关键失败与决策集中在本文；公开结果只保留当前协议下必要的证据。

教程按机制递进，直接引用这一套当前源码，而不是再复制六套教学实现。这样读者先学清楚“现在怎样工作”，再选择是否理解“为什么走到这里”。故事写法参考[购物 Agent 配套文章](https://yyhdbl.github.io/)，教学组织参考 [learn-claude-code](https://github.com/shareAI-lab/learn-claude-code)。

## 仍未解决的问题

当前 test 是与训练隔离但已多次查看的留出集，不是全新盲测；当前主对照缺少多种子验证，相关性推理 SFT 本身还缺完整 test 单独评测。检索环境只覆盖固定候选语料，VCR 不验证任意自然语言推理，也不保证更多证据就会带来更好的答案。

下一步值得回答的，不是再添加多少种算法，而是：更可靠的中间判断如何转化为稳定的最终答题收益？回答它需要新的、事先冻结的评测与足够的重复实验，不能从现在的最高单次 EM 推导出来。

## 证据来源与归档边界

本文根据整理前的初始实验报告、算法对照报告、教师试采集诊断、过程奖励诊断、调参/种子确认记录以及后续方法门控与训练记录编写。旧报告和旧 Git 对象不进入新发布历史，历史部分是归纳叙述，不是重新执行所有旧实验。

当前数值可从 [results/current.json](../results/current.json) 与 `python report.py` 核对。新发布代码的 CPU 检查验证了环境、工具循环、mask 与恢复等契约；没有为这次整理重新执行 GPU 全训练，因此既有成绩不能标成“迁移后新跑结果”。
